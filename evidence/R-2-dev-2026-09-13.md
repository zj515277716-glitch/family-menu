## 2. 实现要点

### 2.1 匹配口径（allergen.ts，对齐任务卡定案）

- 规则源：DB `ExclusionRule` 全量动态读取（`findMany()` 无 where，零硬编码规则文本）。
- INGREDIENT 规则：`nameSet = {targetId, target行.name, ...target行.aliases}`（targetId 经 DB Ingredient 行 join 补全，join 不到仅含 targetId）；食材侧 names = `{dbId, name, ...aliases, ...dbAliases}`；**精确等值**求交，optional 一视同仁（对齐 `packages/engine/src/safety.ts` checkIngredientScope 信息面）。
- TAG 规则：食材 name/aliases/dbAliases 任一**子串**包含 targetTag 即命中（宽口径，纵深补位 engine TAG 通道不查 name/aliases 的缺口——T-C07 S-3 定案）；菜 `flavorTags` 含 targetTag = 已标注，不产出 finding（engine 会拦，管线放行）。
- DISH scope 规则：不在管线检测面（新导入菜无稳定 id），跳过（代码注释已说明）。
- 处置分级：HARD 未标注 → blocked（默认拒绝）；HARD + `--allow-allergen-draft` → 放行+豁免警告；SOFT 未标注 → 放行+警告；已标注/无命中 → 放行无警告；空规则集 → findings 空，零影响。
- INGREDIENT 规则无 targetTag，不存在标注面：命中即 finding（无「已标注放行」判定）。

### 2.2 fm-import（AC1+AC3）

- 流程：文件检查 → origin 归一（既有）→ `prepareDraftDish`（fail-fast）→ category 警告（stderr，不阻断不改退出码）→ 建 writer 连接 → 读规则（打印行数与 HARD/SOFT 分布）→ 按名查 DB 食材行合成 profiles → `checkDishAllergen` → `resolveAllergenDecision` → blocked 则输出命中明细+豁免提示、`process.exitCode=2`（先 `$disconnect` 再退出）；否则放行，dry-run 走既有输出格式，非 dry-run 走既有 `importDraft`。
- dry-run 同样执行过敏原校验；DB 不可达 → 抛错 → exit 1（fail-closed 自身错误口径）。
- 拦截 exit 2 与自身错误 exit 1 分离（对齐 batch-fetch exit 2 先例）。

### 2.3 fm-publish-check（AC2+AC4）

- 只读：仅 `exclusionRule.findMany` / `ingredient.findMany` / `dish.findMany`（include DishIngredient.ingredient），全程零写库语句。
- 扫 `status IN ('DRAFT','TESTED')` 全部菜，同口径检测；报告结构 `{scannedAt, statusFilter, ruleCounts, scannedCount, gapDishCount, gaps[], nonStandardCategory}`；`--json` 输出结构化 JSON，缺省人类可读全文。
- 退出码：0=无缺口 / 2=有缺口 / 1=自身错误（参数非法、DB 不可达）。
- `--status` 过滤：大小写不敏感、逗号分隔、去重保序，白名单外抛错；缺省全扫。
- 非标 category 计数按 name+category 去重（同名食材跨菜引用只计一次）。
