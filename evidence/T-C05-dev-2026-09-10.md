## 4. 执行过程中发现并修复的问题（先复现再修复）

### 4.1 原生 SQL INSERT 违反 NOT NULL（Prisma cuid 语义）
- **现象**：首次全量写入时 `INSERT INTO "Ingredient"` 报 null value in column "id" violates not-null constraint。
- **根因**：Prisma `@default(cuid())` 仅在 client 层生成 id，PG DDL 层无默认值；原生 SQL INSERT 不带 id 必失败。
- **修复**：脚本内置简化 cuid 生成器（`c` + 时间戳36进制 + 计数器 + 随机段，格式对齐），INSERT `Ingredient` 与 `DishIngredient` 均显式生成 id。已验证入库的 id 与既有行形态一致。

### 4.2 知识库 JSON 首写格式损坏（自纠）
- **现象**：首版手写排版出现非法引号/缺值，Node 解析失败。
- **修复**：整体重写为干净格式，`node -e "require('./ingredients-draft.json')"` 解析通过（29 dishes / 258 ingredients 全合法，字段齐全）。

### 4.3 PowerShell 重定向/内联引号问题（环境自纠）
- PowerShell `>` 默认 UTF-16 及双引号转义与 Node 冲突，改为控制台直出/独立 .cjs 文件执行，不影响任何脚本结果。
