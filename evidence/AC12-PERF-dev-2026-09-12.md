## 3. AC3：噪声来源分析与历史失败对照

### 3.1 4 次历史失败 vs 本机实测复现带

| 历史失败 | 失败值 (ms) | 发生轨 | 落入本机实测哪个带 | 是否无需压力即可复现 |
|---|---|---|---|---|
| DEPLOY-01 | 50.3714 | 非 coverage 50ms | 空闲尾部带（A/B 实测 50.04–52.23） | 是（A-06=50.0389 同量级） |
| DEPLOY-02 V1b | 50.19 | 非 coverage 50ms | 空闲尾部带 | 是 |
| DEPLOY-02 V1b | 57.86 | 非 coverage 50ms | 轻压力带（B2 实测 51.24–68.22） | 否，需秒级背景劣化（B2 证明可达） |
| DEPLOY-03 LM_R1 | 51.764 | 非 coverage 50ms | 空闲尾部带（A-02=51.758，与 51.764 前 4 位有效数字相同，Δ≈0.006ms，属数值巧合，见 §5.5） | 是 |

### 3.2 归因结论

**受控环境分布能够解释全部 4 次历史失败**，证据链：

1. **量级吻合**：历史失败 4 值（50.19/50.37/51.76/57.86）全部落在本机实测可复现带 [50.04, 68.22] 内；其中 3 值落在"空闲尾部带"（本机无外加压力即产出 50.04–52.23ms 的失败值，复现率 20%），1 值（57.86）落在 CPU 压力带。
2. **失败模式判定**：min-of-3 内部三次尝试同跑次高度同涨同落（B-04: 52.2/57.0/56.5；B2 各跑全超），且失败呈**秒级持续性**（整个 vitest 进程生命周期内劣化）而非毫秒级毛刺——指向 **Windows 桌面环境的 CPU 调度抢占/Defender 实时扫描等秒级背景劣化**，而非 GC 毛刺或 JIT 噪声（后者已被预热+min-of-3 覆盖）。
3. **复刻性**：真实门禁命令（Track A）在本机即以 20% 复现率复现 flaky，失败值与历史前 4 位有效数字相同（A-02=51.758 vs LM_R1=51.764，Δ≈0.006ms，属数值巧合，见 §5.5），无需假设任何代码/数据/引擎非确定性。`generateLargeLibrary` 为确定性纯函数，同输入同输出，可排除。
4. **负载相关性弱但因果性强**：瞬时 load% 快照区分度低——B 轨口径：失败跑均值 32.5% vs 通过跑 24%；A 轨权威门禁口径：失败跑 19.0% vs 通过跑 23.3%（方向反转）；A-20 在 0% 快照下仍失败。两轨均显示瞬时快照区分度低，CPU 压力轨迹需更细粒度观测（快照为每跑开始前的瞬时值，非全程积分）；但**持续**负载的因果性由 B2 铁证（4 压测进程 → 100% 失败、min 上移至 51–68ms）。
5. **根因归纳**（按权重排序）：
   - ① **阈值无余量**：50ms ≈ 本机单次尝试中位数（50.040ms），阈值切在分布中位而非尾部之外；
   - ② **噪声属秒级环境劣化**：min-of-N 采样、预热等进程内方法学手段对抗不了（B2: 10/10 失败）；
   - ③ **桌面环境背景负载波动**：Defender 扫描等造成时段性分布整体漂移（前后半 median 48.973→47.730，失败 4/10→0/10）；
   - ④ coverage 轨 200ms 的 4 倍余量从未失败，反向佐证 ①。

## 4. AC4：候选处置方案评估（diff 预览，均未实施）

> 评估基准（本机实测）：空闲 min-of-3：min 44.94 / median 48.79 / P95 51.55 / P99 52.23，FAIL 率 20%；持续压力 min-of-3：51.24–68.22，FAIL 率 100%。目标：消除 flaky 且尽量保留对真实性能回归的检出能力。

### C1：放宽非 coverage 阈值 50 → 80ms

```diff
--- a/packages/engine/test/score.spec.ts
+++ b/packages/engine/test/score.spec.ts
@@ -792,1
-  const threshold = process.env.VITEST_COVERAGE === '1' ? 200 : 50;
+  const threshold = process.env.VITEST_COVERAGE === '1' ? 200 : 80;
```

- **效果**：80ms > B2 压力组 max(68.22)+余量 → 本机 flaky 完全归零；60ms 则不够（压力组 10 跑中 min≥51.2，5/10 的 min 仍 >60，8/10 >55）。60ms 阈值下压力组仍有假红，80ms 依据成立。
- **误报（假红）**：消除。**漏报（假绿）风险**：中等——阈值余量从 ~2%（50/49）放宽到 ~78%（80/45），性能劣化 30% 级（如 45→60ms）将无感通过门禁；偏离 AC12 字面定义「<50ms」，需主控+用户批准。
- **维护成本**：极低（一行）；无需新依赖。
- **数据支撑等级**：强（B2 直接给出 80ms 的下界依据）。

### C2：多次连跑判据（门禁层连跑 3 次、任一通过即通过，best-of-3 OR 链；或测试级 retry: 2）

方案 C2a（vitest 测试级重试，同 worker 进程重跑测试体）：

```diff
--- a/packages/engine/test/score.spec.ts
+++ b/packages/engine/test/score.spec.ts
@@ -771,1
-  it('千套菜单 recommend 调用性能 < 50ms（AC12）', () => {
+  it('千套菜单 recommend 调用性能 < 50ms（AC12）', { retry: 2 }, () => {
```

方案 C2b（门禁层连跑判据，脚本预览，落在调用方而非本 spec）：

```diff
--- a/package.json（根，示意）
+++ b/package.json（根，示意）
@@
-  "test": "vitest run --no-file-parallelism",
+  "test": "vitest run --no-file-parallelism",
+  "test:gate": "pnpm test || pnpm test || pnpm test"
```

- **效果**：retry=2（共 3 次尝试）与门禁层 best-of-3 同为「3 次尝试、任一通过即通过」语义。每跑失败率 p=0.2（点估计）下，残余假红 = p³ ≈ 0.2³ = 0.8%（独立性假设）；敏感性：p 取 20% 假红率的 Wilson 95% CI ≈[8.1%, 41.6%]（见 2.2/2.3）时，下界 0.081 → 残余约 0.05%，上界 0.416 → 残余约 7.2%——即点估计 0.8%，上限情景可达数个百分点。独立性假设之外：秒级劣化时长若 >3 跑总时长则相关性升高，残余高于上述估计。C2b 真正跨进程，对秒级劣化的免疫强于 C2a（C2a 同 worker 进程，进程级劣化会重复失败）。
- **语义对照说明**：若采用多数决「3 取 2」语义（3 次中 2 次失败即红），真残余为 3p²(1−p)+p³ = 10.4%（p=0.2），**不在本方案之列**——本方案是 best-of-3 OR 链（diff 中 `||` 链，任一通过即通过），非多数决。
- **误报**：基本消除（点估计 0.8%，上限情景见上）。**漏报**：**危险点**——持续但轻微的回归（如 45→52ms 稳定劣化）会被重试"救活"，真实回归被掩盖；重大回归（>55–60ms，即 3 跑全超）仍能被检出。
- **维护成本**：低（一行或一条脚本）；无新依赖。**墙钟成本**：全量套件单跑约 10s（A2 轨实测，非冷启动跑 wall 9.46–10.01s），best-of-3 门禁最长约 30s，失败场景墙钟 ×3。
- **数据支撑等级**：强（分布直接给出 0.2 的基础失败率与重试收益公式）。

### 推荐排序

| 排序 | 方案 | 理由 |
|---|---|---|
| **1** | **C2b（门禁层跨进程连跑 3 次、任一通过即通过，best-of-3 OR 链）**，可选叠加 C2a | 唯一同时做到：保留 50ms 的 AC12 字面语义 + 残余假红点估计 0.8%（上限情景可达数个百分点，见 C2 敏感性）+ 重大回归仍可检出。排名第 1 的非量化理由：①保留 50ms 语义，无需产品层批准；②跨进程隔离，与本仓历史门禁「每次单进程一跑」的裁决方法学同构；③实施成本一行。缺点是轻微持续回归（50–55ms）会被掩盖——可用"失败跑记录 minElapsed 数值"缓解 |
| **2** | **C1（50→80ms）** | 最简单、彻底（含压力环境全免疫）；代价是掩盖 <80ms 级真实回归 + 偏离 AC12 字面定义需主控/用户批准；若团队更在意"零打扰"可选此项 |
| **3** | **C3（min-of-7）** | 一行改动、零语义争议，可与 C1/C2 叠加；但数据证明它不解决主因（秒级劣化），单独采用残余 1–4% |
| **4** | C4（非门禁化） | 失去全部保护，不单独推荐 |

**组合建议**：C2b + C3 叠加（门禁层 best-of-3 + 测试内 min-of-7），既压毛刺又压秒级劣化，且 50ms 语义不变；若主控希望零 flaky 优先且接受偏离 AC12 字面，则 C1(80ms) + C3 最省维护。
