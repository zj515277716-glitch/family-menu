# R-9 任务卡：DRAFT 内容 HTTP 只读口（GET /api/dishes 列表 + 详情）

> 派发：主控 PM｜日期：2026-09-13｜执行：fm-dev｜性质：实现卡（apps/api 内改动，不涉 shared）
> 来源：T-C03 审查建议级 R-9（[evidence/T-C03-2026-09-10.md](./T-C03-2026-09-10.md) L38）：「DRAFT 内容无 HTTP 只读口（审阅 FETCHED 草稿需直查 PG）——登记待内容轨道后续卡」。
> 主控开卡前探查定案（2026-09-13，全只读）：
> ① apps/api 现有 3 路由模块（family/recommend/plans）+ 静态 /images/**，**无任何 dish 读取端点**（rds-1 段「API 无 dishes 详情端点系 10 条路由清单设计内」）——审阅 DRAFT/FETCHED 草稿只能直查 PG；
> ② shared DishSchema 已含 origin/imageUrl/sourceUrl/sourceSite/licenseNote（dish.ts L38-60，origin L51）——响应复用既有契约**不涉 shared 变更**；shared 无现成 dish 列表响应 schema；嵌套 dish.ingredients 的 view 形状（ingredientName 等）shared 亦无 schema（CandidateSchema.menu=z.unknown()）；
> ③ mappers.ts toDishView 投影**缺 origin**（DishRow 接口 L41-59 无 origin 字段）——若直接 DishSchema.parse，origin 走 zod default('LLM_DRAFT') 会**谎报 FETCHED 行**（审阅场景实质正确性缺陷）；
> ④ fm-import 入库前过 DraftFileSchema.parse（=DishSchema.extend，tools/content-pipeline/src/import.ts L113/L176）——管线入库行必然符合 DishSchema 顶层形状，列表端点严格 parse 有兜底依据；
> ⑤ authHook 为全局 preHandler（app.ts L71），/images/** 同口径鉴权——新端点自动覆盖无需豁免逻辑。

## 背景

T-C03 打通内容轨道三段式（采集→转换→入库）后，草稿审阅是产品流程的必要环节（DRAFT→TESTED→PUBLISHED 人工把关）。当前入库后的草稿无任何 HTTP 读取口，人工审阅/微调对照需直连 PG 手工查询，效率低且易误操作。本卡给内容轨道补一个只读口（对齐「路由薄、逻辑在 services」既有架构），审阅动作可经 curl/浏览器（带口令 cookie）完成。

## 目标

新增 dishes 只读路由模块（列表 + 详情两个 GET 端点）+ mapper origin 投影补齐，全部约束在 apps/api 内，不涉 packages/shared 修改、不碰 engine、不碰 DB schema、零写库。

## AC（逐条 [✓]/[✗] 自检，证据落盘 evidence/R-9-dev-2026-09-13.md）

- **AC1 GET /api/dishes 列表端点**：`?status=` 可选过滤——值域 DRAFT/TESTED/PUBLISHED（消费 shared ContentStatusSchema，白名单外 400；支持逗号分隔多值去重保序；缺省=全部）；响应=shared DishSchema 数组（`z.array(DishSchema)` 本地组合，不改 shared）；排序 id asc（Dish 无显式 createdAt/updatedAt 列，cuid 时间有序=入库顺序，确定性防无 ORDER BY 同类问题）；路由薄原则对齐 plans.ts 先例（safeParse 校验 + service + 响应 parse）；app.ts 注册新路由模块，且 L118「10 条路由」注释同步更新为实数口径（注明 R-9 依据）。
- **AC2 GET /api/dishes/:id 详情端点**：Dish 全字段 + ingredients 用料清单（DishIngredient→Ingredient join，view 形状 ingredientId/ingredientName/aliases/category/defaultUnit/qty/unit/optional 对齐 engine DishIngredientView 类型）；不存在 → 404（NotFoundError 先例口径）；响应 schema 本地组合（DishSchema.extend 或等价形态，ingredients 部分本地 zod 定义——shared 无此形状 schema，本地组合不涉契约变更）。
- **AC3 origin 投影补齐（正确性关键点）**：mappers.ts DishRow 接口补 origin 字段 + toDishView 投影 origin（engine DishView 无 origin 字段，**禁改 engine**——用本地交叉类型扩展，先例=DishMediaView 媒体字段形态）；zod default('LLM_DRAFT') 不得吞掉 FETCHED 实值——用本地库 FETCHED 菜（29 道管线入库菜）实测验证 origin 投影正确。
- **AC4 鉴权与只读**：全局 authHook 自动覆盖（无 cookie 401，与 /images/ 同口径，不新增豁免逻辑）；端点全程 findMany/findUnique **零写库**（代码中不得新增任何写库语句）。
- **AC5 测试与回归**：新增 spec（apps/api/test 先例模式：buildApp + inject + 真实 PG，对齐 put-exclusions.spec.ts 口径——SELECT 1 gate 防假绿、若需造测试行用 `rm9-` 前缀隔离 + afterAll 清理 + 断言零残留）；覆盖至少：无 cookie 401 / 列表缺省全量 + status 单值 + 多值 + 非法值 400 / 详情 200 含 ingredients + 404 / origin 投影 FETCHED 实测 / **存量全量行 DishSchema.parse 幂等验证**（防畸形 DRAFT 行挂全列表——fm-import DraftFileSchema 先例佐证应全过，若有失败行如实报告不自行改数据）；真实执行根 `pnpm test`（基线 432/432 + 新增全绿）与 `pnpm test:taboo`（95/95）+ apps/api typecheck/build EXIT=0，报告记录命令+退出码+数字。
- **AC6 约束与零侵入**：零 packages/shared 改动、零新增 npm 依赖、运行时零 LLM API；改动限定 apps/api 内（新 routes/dishes.ts + service 层（新建 dishesService 或按最小改动内聚既有 service，裁量报告列明）+ mappers.ts origin 补齐 + app.ts 注册 + test）；不碰 tools/content-pipeline、apps/h5、packages/engine、packages/list-merger、prisma。
