**根因定位**（实测输出 + vitest 4.1.10 源码证据）：

1. `pnpm --filter @family-menu/shared test` 以 packages/shared 为 cwd 执行 script `vitest run`（裸，无 `--root`、无本地 vitest/vite 配置文件）。
2. vitest CLI 解析顶层配置：`node_modules/.pnpm/vitest@4.1.10_*/node_modules/vitest/dist/chunks/cli-api.BK8pd4xc.js` L14210-14211：
   - `root = options.root || process.cwd()` → root = packages/shared（RUN 行打印 `D:/codex/family-menu/packages/shared` 证实）；
   - 未显式 `--config` 时 `configPath = any(configFiles, { cwd: root })`。
3. `any()` / `up()` 实现在同包 `dist/chunks/index.og1WyBLx.js` L42-73：`up()` 从 cwd 逐级 `dirname` **向上遍历直到文件系统根**，`any()` 在每层目录按序探测 vitest.config.* / vite.config.* 并返回第一个命中 → 在第 2 层 `D:/codex/family-menu` 命中根 `vitest.config.ts`。
4. 于是根配置的 `test.include = ['packages/*/test/**/*.spec.ts', 'apps/*/test/**/*.spec.ts', 'tools/*/test/**/*.spec.ts']` 被继承，但 **glob 相对 root=packages/shared 解析**（若相对仓库根解析必命中多个 spec，与"零匹配"矛盾；RUN 行 root + 空跑输出互证）→ `packages/shared/packages/*/test/**` 等路径不存在 → No test files found → exit 1。
5. **对挂账初步判断的修正**：初步判断"include 模式以子包 cwd 解析无匹配"方向正确，但缺关键环节——shared 无本地配置并不代表 vitest 用默认 include（vitest 默认 include `**/*.{test,spec}.?(c|m)[jt]s?(x)` 反而能命中 `test/schemas.spec.ts`）；空跑的真正机理是 **vitest 4.1.10 配置发现会向上遍历目录树，子包裸 `vitest run` 上溯继承了根配置的 include**，再叠加"glob 相对子包 root 解析"导致零匹配。

## 4. shared 空跑根因结论（备案正文）

一句话：**packages/shared 无本地 vitest 配置，vitest 4.1.10 的配置发现机制（`any(configFiles, {cwd})`）会从 cwd 向上遍历到文件系统根，因此在 packages/shared 下裸 `vitest run` 加载了根 `vitest.config.ts`；其 `include` 三条 glob 相对 root（=cwd=packages/shared）解析后零匹配，导致 `No test files found, exiting with code 1`。**

证据链：
- 实测：空跑输出打印的 include 正是根配置三条 glob，root 为 packages/shared，exit 1（§3 AC3）。
- 源码：vitest 4.1.10 `dist/chunks/cli-api.BK8pd4xc.js` L14210-14211（root/configPath 计算）与 `dist/chunks/index.og1WyBLx.js` L42-73（`up()` 上溯 + `any()` 逐层探测）。
- 反事实佐证：根目录 `pnpm vitest run packages/shared/test/schemas.spec.ts` → 68 passed（DEPLOY-02 报告 §3），证明该 spec 本身完好，空跑纯属配置加载/解析路径问题。
