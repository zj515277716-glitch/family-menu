## 5. 卡外发现（铁律 2 报告，本切片内修复并有审查背书）

**toEventView 事件映射缺陷（严重：历史接受度与多样性评分在真实 API 全程失效）**

- **发现过程**：多样性验证 v1 期待「连续裸推荐轮换」失败；核查确认 GENERATE 事件本就不带 menuId（payload 仅 planId），裸推荐不轮换符合设计。但进一步核查发现真因：`toEventView` 只映射 id/type/createdAt，**payload 整体丢弃**，`EventView.menuId` 永远 undefined → 引擎历史接受度（权重 0.35，最大维度）与近期多样性降权（0.10）在真实 API 中恒取中性分（0.7/0.8），多样性机制实际从未生效。
- **根源追溯**：早期开发时 EventRow 类型与 Prisma 查询不匹配，错误地删字段而非做 join；基线审计早有标记（[BASELINE-2026-09-04.md](./BASELINE-2026-09-04.md) / CURRENT.md 断裂点第 4 条「映射层丢弃反馈内容」）。TP-05 修复了记录侧（三问如实落库），消费侧（评分读取）仍断——本切片补上最后一环。
- **修复内容**：`mappers.ts toEventView` 按 join 规则补齐——LOCK→`payload.menuId`；SWAP_MENU→`payload.newMenuId`；SWAP_DISH→`payload.dishId`；COOKED→`plan.lockedMenuId` + taste 映射（good→success/ok→partial/fail→fail，与 addFeedback 写 CookLog 同一映射）+ `willRepeat`；NOT_COOKED/GENERATE/VIEW/REPEAT/RESCALE 不带 menuId（没做成/未选定，不参与「7 天内已做过」降权）。`planService.ts loadEventViews` 查询 include `plan.lockedMenuId`。
- **生效证据**：修复前 15min 档候选 [02, 01, 03] → 修复后 [02, 03, 04]（此前 e2e 冒烟锁定的 menu-01 被 7 天降权掉出）；e2e 冒烟第二次推荐前三含两套周末管线菜单（§2.3）。
- **定性**：本属 WP-04 范畴的卡外问题，但直接卡住 TP-06 自身完成标志「多样性可复现」（修复前无多样性可言），按用户规范「技术失败后台继续修复」处理，fm-reviewer 只读审查 A-E 全 PASS 后纳入本切片提交。
- **教训记入**：引擎单测此前全绿，因测试夹具直接构造带 menuId 的 EventView、未经真实映射层——单测与集成断层，后续触碰评分链路的切片必须以真实 API 端到端验证（本切片 e2e+多样性验证即按此执行）。

**流程记录**：

1. verify-diversity v1 两项失败均为验证脚本断言写错（期待裸推荐轮换），产品无缺陷；v2 按真实用户流程「推荐→锁定」重写后 6/6。
