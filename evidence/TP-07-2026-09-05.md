## 3. 卡外发现与修复（铁律 2 报告，本切片内修复）

**公网 GET /api/family/exclusions 首测 400（契约零改动修复）**

- **现象**：部署完成后公网冒烟 exclusions 返回 400。
- **根因**：Prisma 可空列（targetId/targetTag/note）读出来是 `null`，而 shared 契约 zod `.optional()` 只接受 `undefined` 不接受 `null` → 响应过 `GetExclusionsResponseSchema.parse` 时报校验失败 → 400。本地开发库同数据曾未暴露（历史查询路径差异），公网真实环境直查暴露。
- **修复**：`apps/api/src/services/planService.ts` getExclusions 服务层归一化 `targetId: r.targetId ?? undefined` 等三字段——null 转 undefined，契约（packages/shared）零改动、零迁移。
- **生效证据**：重建镜像部署后公网同接口 200，2 条规则完整返回（§2.1 #7）；本地 apps/api 68/68 全过（§2.4）。
- **定性**：WP-04 范畴的服务层映射缺陷，直接卡住 TP-07 完成标志「冒烟清单全绿」，按用户规范「技术失败后台继续修复」处理，纳入本切片提交。

## 5. 环境经验（定型，供后续复用）

1. **服务器操作定型**：长等待/含 sleep 的复合 ssh 命令输出必被沙箱吞掉——只用短小瞬时 ssh 轮询 + 把脚本 scp 上服务器执行、结果落文件再取回。
2. **PowerShell 陷阱**：`echo.` 是 cmd 语法；内联 `powershell -Command` 的 `$` 变量被外层转义吞掉；`curl.exe -d "含引号JSON"` 静默失败——对策：请求体写文件用 `-d "@file"`，JSON 解析用 node 脚本不用内联 PS。
3. **双并发构建共存**：一次「看似中断」的 docker build 实际远端进程存活并与第二次构建并行，BuildKit 多客户端共享层缓存不冲突；`docker compose up -d` 幂等，容器被重建一次、第二次 up 为 no-op，无副作用。
4. **镜像导出阶段 6-10 分钟无日志**（exporting layers 不写日志），耐心轮询不误判为卡死。
5. vitest 配置仅在仓库根：`pnpm test apps/api` 可跑，`pnpm --filter` 方式报 No test files found（TP-05 起多次复踩，本次定型）。
