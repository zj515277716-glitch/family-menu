## 3. 契约变更（DEC-014，先评估后实施）

- `ShoppingListItemSchema`：`checked` required（旧快照 JSON 兼容由 api 层归一补默认 false）；新增 optional `alreadyHave`（必消标记）与 `pantryStaple`（常备标记）——optional 保证旧存量清单报文仍合法。
- 新增 `RescaleShoppingListRequestSchema`：`{ people: z.number().int().min(1) }`，无上限（上限 1-20 是 UI 防误触约定，不进契约）。
- `EventType` 新增 `RESCALE`，事件 payload 记录 `{ from, to }`。
- 新增路由 `POST /api/plans/:id/shopping-list/rescale`：服务端重算清单（按 ingredientId 保留勾选与标记）、同步 plan.context.people、写 RESCALE 事件；未锁定计划 409（PlanStateError）。
- 架构裁决（DEC-014）：常备调料**标记保留不删除**（C-8「就按这个买」由用户自己确认，不替用户做主）；取整在合并后一次性执行 `Math.max(1, Math.ceil(qty))`（保底 1 份，杜绝 0 量条目）；BASE_SERVINGS=4（确认书基准）。

## 5. 卡外发现与流程记录（按铁律 2 报告，不顺手修改）

1. **prisma migrate 被沙箱拦截（环境限制）**：`prisma migrate dev` 两次被沙箱以 "Not allow operate files: C:\Users\15273\AppData\Roaming\prisma-nodejs\Config\commands.json" 拒绝；尝试 `CHECKPOINT_DISABLE` / `PRISMA_HIDE_UPDATE_MESSAGE` / `PRISMA_TELEMETRY_DISABLED` 三个环境变量均绕不开。**定型「手动 SQL 迁移路线」**：手写 migration.sql + `prisma.$executeRawUnsafe("ALTER TYPE ... ADD VALUE IF NOT EXISTS 'RESCALE'")` 应用 + INSERT 登记 `_prisma_migrations`（checksum 为 migration.sql 内容 sha384 hex 的**前 64 字符**——Prisma 实际存储口径，首版用全 96 字符触发 varchar(64) 超长报错）+ 查询 `enum_range` 验证。迁移文件已正常入库，将来在非沙箱环境 `prisma migrate deploy` 可正常识别该迁移（checksum 与 Prisma 口径一致）。此经验供 TP-05+ 及部署环境复用。

3. swapPlan「全换」分支 mustUse 原文未映射（TP-02 移交项，仍遗留）：「整套换」在 TECHNICAL-PLAN 推迟清单，不在本切片范围，继续顺延。
