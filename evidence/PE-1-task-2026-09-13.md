## 一、背景与问题定论（勿重复评估，直接实现）

1. **风险定论（verify V5 已实证，无需复评）**：`planService.putExclusions`（apps/api/src/services/planService.ts L352-370）事务内 `deleteMany({where:{familyId:FAMILY_ID}})` + `createMany(payload)` 全量替换——一次前端保存（payload 不含 seed 规则，如 H5 设置页本地 state 为空/加载失败后保存）即清除 seed 3 条规则，花生食材级 HARD 拦截力归零；`createMany({data:[]})` 经实测返回 `{"count":0}` **NOOP 未抛错**（非 500 分支），即 `PUT([])` 若提交=全表清空。
2. **H5 缺口**：apps/h5/src/pages/setup/index.tsx `loadRule` L53-73 GET exclusions 失败仅 console.error、state 保持 `[]`，用户仍可保存 → PUT([]) 全清；`handleSave` L75-108 直接 `api.putExclusions(exclusions)` 本地 state 全量回传，其它端新增的规则会被静默覆盖。
3. **已知边界（须在注释与产品口径如实标注，不得隐瞒）**：
   - S-4：db:seed 重放（seed.ts L115-129 upsert `update:{}`）可恢复**被误删**的 seed 行，但**不修复同 id 行内容被篡改**；
   - S-5：H5 合并语义下用户在 UI 删除 seed 规则后保存会被复活——家庭自用场景影响可接受（主控裁决），正式解法为长期方案 3（source 列标记 SEED/USER，涉 shared 契约+迁移双变更，**另立卡不在本卡范围**）。

## 二、实施内容（主控裁决短期组合 1+4+5）

### ① API 层 seed 保护（apps/api/src/services/planService.ts putExclusions）

- `deleteMany` 排除 seed 前缀行：`where: { familyId: FAMILY_ID, id: { not: { startsWith: 'seed-' } } }`——只删用户行，seed 行永不删；
- `createMany` 过滤 payload 中 `id.startsWith('seed-')` 的行（防主键冲突 P2002 整批失败）；过滤后为空数组是合法 NOOP（S-2 已定论）；
- 保持「对用户行的全量替换」语义与 `return this.getExclusions()` 返回口径不变；familyId 强制覆盖逻辑不变。

### ④ H5 兜底（apps/h5/src/pages/setup/index.tsx）

- `handleSave` 持久化禁忌前 **re-GET /api/family/exclusions**，与本地 `exclusions` state 按 id 合并去重（**本地版本优先**，远端独有行追加）后再 PUT——兜住「本地缺 seed 行」与「其它端新增行被覆盖」两类场景；
- `loadRule` 中 exclusions GET **失败时禁用保存**（保存按钮 disabled + 提示），成功则恢复——防止加载失败空 state 覆盖库；familyRule 加载失败行为维持现状（catch + toast）；
  - **【S1 勘误注记 · 2026-09-13 主控代加（review S1）】**「维持现状（catch + toast）」对现状描述失实：改动前 familyRule 失败路径实为 console.error 无 toast（T-C07-FIX-dev L13 佐证）；dev 按「维持现状」落为 console.error，与文字不符但与「不改变既有行为」语义一致，判定实现正确、任务书表述勘误备案。
- 注意 S-5 副作用如实注释：合并语义下 UI 删除的 seed 规则保存后被复活，正式解法长期方案 3。
  - **【T-1 裁决注记 · 2026-09-13 主控（review T-1，合并前置动作）】** review 发现合并语义会复活**用户行**删除（未披露行为回归）。主控裁决产品口径：**seed 行=出厂配置，受 API 层保护不可经 UI 删除（保存后由 API 层 seed 保护复活，S-5 语义保持）；用户行=用户数据，删除须持久化**——实现采用 removedIds 集合（removeExclusion 记录待删 id，合并时从远端追加中排除，保存成功后清空）；S2 搭车修复（exclusionsLoadFailed 初始 true，加载中禁保存）。披露补齐随返工执行。
