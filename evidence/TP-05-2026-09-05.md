PASS | 无反馈时 GET /feedback 404（初始化空表单依据）
PASS | 做了缺 taste 拒绝 400（条件必填生效）

PASS | 覆盖重提（翻车）200（didCook=true,taste=fail,willRepeat=false）
PASS | append-only：反馈事件累计 2 条（旧事件不删）

## 3. 契约变更（DEC-015，先评估后实施）

- `FeedbackRequestSchema` 重写为三问模型：`didCook: boolean`（必填）、`taste?: 'good'|'ok'|'fail'`（superRefine：didCook=true 必填、false 不得传）、`willRepeat: boolean`（必填，没做也答）、`actualMinutes?: int`（选填，PD-006）。旧字段 `result/cookResult/failPoints` 直接移除（breaking，v0.5→v0.6 明示；消费面仅自家 h5，grep 证实无第三方消费者，调用方与契约同 PR 升级）。
- 新增 `TasteSchema`、`FeedbackResponseSchema`（响应侧 taste/willRepeat optional 为旧数据宽松解析，不编造）；删除 `FeedbackResultSchema`/`CookResultSchema` 及类型导出；`result='repeat'` 语义 hack 消除，REPEAT 事件回归 repeatPlan 专属语义。
- 事件与存储映射（零迁移，EventType/prisma/schema.prisma 零改动）：didCook=true→Event COOKED `payload={taste,willRepeat,actualMinutes?}` + CookLog append（result 单向映射 good→success/ok→partial/fail→fail，failPoints=null，dishId 沿用现状）；didCook=false→Event NOT_COOKED（payload 无 taste）不写 CookLog；Plan.status：didCook→COOKED / 否则→SKIPPED（willRepeat 不影响 status）。
- 覆盖重提=append-only 事件流 + GET 取 createdAt 最新一条（didCook 由事件 type 派生）；feedback 写/读均用 findUnique+NotFoundError，不走 requireLockedPlan（DEC-015 裁决 4）。
- C-11 标签派生规则钉死（可测试）：taste=fail→红 > taste=ok→黄 > didCook=false 或 willRepeat=false→灰 > 其余→绿（味道事实优先于意愿）；「约 N 分钟」=actualMinutes 有值才显示。
- 本轮不做学习（裁决 6）：packages/engine 零改动，评分不读反馈；「反馈学习闭环」在以后再做清单（PD-006）。CURRENT.md 断裂点第 4 条（历史反馈恒中性）的**记录侧**已修复（三问如实落 Event payload 与 CookLog），**评分消费侧**推迟至学习闭环切片。

## 5. 卡外发现与流程记录（按铁律 2 报告，不顺手修改）

1. **NutUI Input 与 Taro Input 类型差异**：`@tarojs/components` 的 Input 无 `onChange:(v:string)=>void` 签名（h5 类型检查 TS2322/TS7006），NutUI `@nutui/nutui-react-taro` 的 Input 有（setup 页先例）。feedback 页耗时输入改用 NutUI Input（tarojs components 只留 View/Text），类型检查恢复 0 错。经验：Taro 环境下受控输入组件优先用 NutUI 导出。
2. **vitest 配置仅在仓库根**：`pnpm --filter @family-menu/engine test` 及在 engine 子目录重跑单文件均报 "No test files found"；单文件重跑须从根执行 `pnpm exec vitest run packages/engine/test/score.spec.ts`（环境经验，TP-04 起多次复踩，本次定型记录）。
3. **e2e 设计期预防**：GENERATE/LOCK 也写带 planId 的事件——反馈事件断言必须按 `type in ['COOKED','NOT_COOKED']` 过滤，否则 append-only 计数被污染（写脚本前 grep event.create 查证，未实际踩坑）。
4. TodoWrite 曾出现重复条目，改 merge:false 全量重建纠正（流程记录）。
5. 承前遗留顺延：swapPlan「全换」分支 mustUse 原文映射（整套换实施时处理）；STATUS.md 旧轨不修；taro build 沙箱限制属 TP-07。
