### 2.3 e2e 迭代记录（两轮均为脚本缺陷，产品代码零缺陷）

## 5. 卡外发现与流程记录（按铁律 2 报告，不顺手修改）

1. **沙箱自动回收长驻服务进程（环境经验）**：`pnpm dev`（web_server 类型）启动报 "Server listening" 后数分钟被沙箱回收（terminal Exited），后续请求 ECONNREFUSED——**长驻服务不可靠，验证类脚本必须自包含**。另有孤儿进程陷阱：StopCommand 只杀 shell 父进程，tsx watch 的 node 子进程残留并占用端口（EADDRINUSE，需 `taskkill /PID <pid> /F` 收尾）。定型「自包含 e2e 模式」：脚本内 buildApp+listen({port:0})+自带 dotenv.config+finally 关闭，执行 `pnpm exec tsx .xxx.mjs`——本切片 e2e 及后续切片 e2e 均按此模式。
2. **taro build 被沙箱中断（范围澄清）**：`pnpm -r build` 中 apps/h5 的 taro build 两次被沙箱以 Ctrl+C 信号杀（exit 3221225786=0xC000013A）；在 apps/h5 cwd 下跑 pnpm 触发 deps-check 自动 install 还报 `[ERR_SQLITE_ERROR]`（pnpm store 索引被拦）。经核对 [TP-01 evidence 第 89 行](./TP-01-2026-09-04.md)：**taro 生产构建与部署属 TP-07 范围**，本切片停止尝试，h5 验证以 `tsc --noEmit` 为准。TP-07 执行时需注意此沙箱限制。
3. **swapPlan「全换」分支 mustUse 原文未映射（TP-02 移交项，仍遗留）**：TP-02 卡外发现第 2 条移交本切片处理，但「整套换」在 TECHNICAL-PLAN 推迟清单、不在 TP-03 范围（本切片范围第 18 行仅含单菜换），故该项**继续顺延**至整套换实施时一并处理（须先过 mapMustUseToIds 映射）。
4. **STATUS.md 旧轨脱节**：STATUS.md 仍为旧协作轨记录，与自主开发轨（CURRENT.md+evidence）脱节。保持原样不修（旧轨仅作追溯对照），本切片继续以 CURRENT.md 为状态事实源。
