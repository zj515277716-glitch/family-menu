4. **关键障碍**：两个 CLI 模块顶层直接 `program.parseAsync(process.argv)`——单测 import 即触发真实执行（publish-check 无必选参数会直接跑 action；import 缺 <file> 会 commander 报错→catch→**测试进程被 process.exit(1) 杀死**）。必须先做可测性守卫重构。

### 可测性守卫方案（定案，行为不变）

`node:url` 的 `pathToFileURL` 判主模块：

```ts
import { pathToFileURL } from 'node:url';
const isMain = process.argv[1] !== undefined
  && import.meta.url === pathToFileURL(process.argv[1]).href;
if (isMain) {
  program.parseAsync(process.argv).catch((err: unknown) => { /* 原文逐字不变 */ });
}
export { program };  // 供单测复用同一 program 实例
```

- tsx 正式口径（pnpm script：`tsx src/cli/publish-check.ts`）：argv[1]=该 .ts 文件绝对路径，与 import.meta.url 匹配 → 行为不变。
- node dist/cli/*.js（bin shim）：argv[1]=该 .js 路径 → 匹配 → 行为不变（dist 直跑 Prisma 路径问题系 R-2 卡外备案①已知限制，非本卡范围）。
- vitest import：argv[1]=vitest bin → 不匹配 → 不执行。
- catch 回调与 process.exit(1) 逻辑**逐字保留**，仅位置移入守卫块。
