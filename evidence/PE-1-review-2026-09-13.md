## 四、重点核验明细

### 1. putExclusions 语义 —— [✓]

planService.ts L365-387 核心代码：

```ts
await prisma.$transaction([
  prisma.exclusionRule.deleteMany({
    where: { familyId: FAMILY_ID, id: { not: { startsWith: 'seed-' } } },
  }),
  prisma.exclusionRule.createMany({
    data: rules.filter((r) => !r.id.startsWith('seed-')).map((r) => ({ /* 全字段 */ })),
  }),
]);
return this.getExclusions();
```

- **deleteMany**：`id: { not: { startsWith: 'seed-' } }` 编译为 `NOT (id LIKE 'seed-%')`；PG LIKE 大小写敏感；id 为非空主键，不存在 NULL 三值逻辑陷阱；过滤面恰好 = 非 `seed-` 前缀行 → seed 3 行免删、用户行全清（全量替换口径保持）。
- **createMany**：入参再滤 `seed-` 前缀，防同 id 主键冲突 P2002，与 deleteMany 形成删除/写入双侧防护；seed 行内容以库内现值为准不被覆盖。
- **事务**：`$transaction([...])` 数组形式，delete+create 同事务原子执行。
- **响应口径**：`return this.getExclusions()` 与改动前一致；family.ts L51-56 路由逻辑未变（safeParse → 400 / putExclusions → GetExclusionsResponseSchema.parse）。
- **注释如实性**：S-4 口径经 seed.ts L115-129 upsert `update:{}` 一手证实（db:seed 重放可恢复被删 seed 行、不修复同 id 内容篡改）；S-5 注释如实但措辞窄化为「seed 规则」（见 T-1）。
