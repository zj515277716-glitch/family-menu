## 需求

1. **S-09 菜品做法（C-5）**：路由参数 `planId/date/slot/dishId`；GET `/api/dishes/:id` 取菜谱，GET `/api/plans?date=` 找 plan 还原同餐上下文。版式照 dish.html：4:3 全出血大图 + 渐变遮罩菜名/餐次/人数/要点 chips；用料按（成人+儿童）/BASE_SERVINGS 缩放凑整（复用 `@family-menu/list-merger` 的 `BASE_SERVINGS`/`roundPurchase`，勿手写公式）；分步做法序号圆点；「‹上一道｜下一道›」限同餐同日；底部操作栏——今天计划为「做完记一笔」（开 S-10），过去日期为「返回历史」（跨日不补记）。三态：加载骨架/菜不存在/服务失败可重试；不显示假图假步骤。
2. **S-10 记一笔（C-5）**：首页餐卡与 S-09 底部打开同一底部弹层，只记这一餐；三问：做了没（必选）→ 好吃/一般/翻车（didCook=true 必选，didCook=false 隐藏且不发送）→ 下次还做吗（必选）；实际耗时选填（15/30/50 快捷块，默认不填，可取消）。同名同餐已有反馈时预填原值；提交 POST `/api/plans/:id/feedback`（带 mealSlot），成功后以 GET feedback 回读为准、关闭弹层、toast「记好了」、首页标签即时更新；失败保留已选、提示「没保存上」可重试。评价可选，不漏评追催、不自动弹窗；空手餐/无菜餐不显示记一笔。
3. **S-11 历史（C-6）**：GET `/api/plans` 全量，按 planDate 本地日分组取每日最新一份（createdAt 倒序），只展示 `planDate < 今天` 的近 14 天；每天显示日期/人数/三餐行（早/中/晚，缺餐用 `displayMealSlots` 如实标「没排上」），每餐显示最多 3 张缩略图、菜名摘要、四色标签（做了·好吃/一般/翻车、没做、还没评价）、已记时间；点菜名进 S-09 复看做法；旧版无 dayPlan 的计划跳过；无记录空态「还没有记录」+「去定明天的餐」；加载/错误可重试三态。
4. **入口接线**：首页「看做法」「记一笔」去掉占位 toast，分别进 S-09 / 开 S-10；历史菜品点击进 S-09；所有按钮有反馈，禁止静默 return。
5. **三态与可访问性**：三屏加载/空/错误齐备；最后一个操作按钮完全可见；时间本地格式、枚举全中文；请求一律走 client.ts（新增 getDish/listPlans/submitFeedback，不新开底层请求）。

## 影响清单（L2 六问）

- **触点**：apps/h5 S-09/S-10/S-11 + 首页入口；apps/api 只读调用 dishes/plans + 既有 feedback 写入；engine/shared/DB 零改动、无迁移。
- **数据**：反馈走既有 Event/CookLog 语义（同日同餐覆盖）；历史只读；不新增表/字段/缓存。
- **兼容**：旧版无 dayPlan 计划在历史跳过；存量反馈无 mealSlot 不按餐展示（按 mealSlot 查询口径）；对外契约不变。
- **回退**：git revert 分支提交即可；无 DB 迁移、无生产数据写入。
- **安全**：沿用既有认证与统一封装；不新增密钥、不调用 LLM、不引入外部服务。
- **环境差异（Q4）**：本卡只消费现有 API；反馈写入仅发生在真实使用/本地验收，本地便携 PG 与生产 RDS 分叉，页面验收只证明 UI 与接口语义，不代表生产数据；生产冻结，不发版、不写生产数据。
- **前端同步/缓存（Q5）**：不引入持久缓存/localStorage；首页提交后以 GET feedback 回读更新内存标签，`useDidShow` 重进刷新；历史每次进入重拉；反馈草稿只存在页面内组件 state（遮罩/取消不丢、刷新页面不保留，符合「同一次编辑会话」口径）。
- **验证**：h5 单测（历史分组/取最新/14 天边界、标签映射、反馈表单显示与校验、缩放）；真实库页面验收（反馈落库/同日同餐覆盖、历史读回、S-09 缩放）；不变量：反馈对象 = 同一 plan+slot、页面末按钮可见、构建不含本机地址/密钥。
