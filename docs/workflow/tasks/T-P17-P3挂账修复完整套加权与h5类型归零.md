## 修复方案定稿（主控技术决策，按此执行）

**① 罚分排序（engine 内部扩展，不动 shared 契约）**：
- engine `RecommendInput`（packages/engine/src/types.ts，engine 内部类型）加 optional 字段 `menuShortageCounts?: Record<string, number>`（menuId → 缺槽说明条数）；
- planService 两条路径（generateRecommendation / swapPlan 全换分支）从 `composition.slotShortages` 计算 `Object.entries(...).map(([id, arr]) => [id, arr.length])` 传入 recommend；
- recommend.ts 排序：`scored.sort` 改为按 `score - SHORTAGE_PENALTY × (menuShortageCounts?.[menuId] ?? 0)` 降序（同分仍按 menuId 字典序稳定）；`SHORTAGE_PENALTY = 0.1` 写死常量（理由：1 条缺槽≈满分差的 10%，足以让完整套反超短套；两套短缺数相同则回到原分数序）；**score 字段与 breakdown 展示值不动**（罚分仅影响排序）；
- 老调用方不传字段 → penalty=0 → 行为与基线逐位一致。

**② V-2 先复现后定性**：不得跳过复现直接下结论；定性结论写入 dev 报告。

**③ 兜底侧车**：planService.ts L613 改 `reasons: ['替换候选', ...(composition.slotShortages[m.id] ?? [])]`。

**④ h5 归零**：重建 shared dist（pnpm --dir packages/shared build）+ apps/h5/src/pages/dish/index.tsx L282 收窄 `?? ''`（**仅此一处**，不改 toAbsoluteImageUrl 签名、不动其余 h5 文件）。
