> 目标：把风格板 3 套视觉方向落成可手机浏览的对比原型，供产品负责人选定 1 套作为新视觉基准（PD-019 的落地）。

- docs/design/v2/PD-020-confirmation-patch.md（C-2~C-5 流程内容口径）

## 交付

1. **3 套方向 × 3 关键屏**，静态 HTML：方向①暖白极简（#C8541F）／②和风暖木（#B07D4E）／③青瓷清新（#4A9D8F，用户偏好降权但照出）；屏 = a 首页（上：今天三餐含评价标签/下一餐置顶，下：定明天的餐）＋ b 三餐菜单（早中晚分区+必消横幅+换一道/换一餐/换一批）＋ c 采购清单+备菜建议（合并去重/标已有/今晚预处理与明早先做两段）。
2. **索引页**（3×3 矩阵入口，手机首屏直达任一页）。
3. 存放 `docs/design/v2/prototypes/`（index.html + style-1|2|3/{a,b,c}.html），自包含 CSS（不引外部框架、不定组件库——比的是风格不是库）。
4. **手机可开链接**：tools/preview-server.mjs（8888，绑 0.0.0.0）起服，给出局域网 IP 链接并 curl 验证 200；服务保持后台运行（终端挂起即可，报告注明如何重启）。
5. 每套 ≤半页设计要点说明（prototypes/README.md：配色/字阶/卡片语言/与偏好表的对应），附 Playwright 或等效截图（375×812）存 evidence/T-Q07/。

## 约束

- 文案全部真实中文家庭菜谱语境（番茄炒蛋、清蒸鲈鱼这类真实菜名与真实食材量），禁止 lorem ipsum 与英文占位。
- 菜品图位一律「占位色块+菜名文字」并标注「实拍图位」（DEC-007：菜品图试做实拍，原型不生成写实菜品图、不用 AI 菜品图）。
- 长辈可用：正文字号 ≥15px 等效、主按钮高度 ≥44px、关键操作一屏内直达；三态意识（至少在清单屏体现「标已有」态）。
- 只动 docs/design/v2/prototypes/ 与 evidence/T-Q07/；门禁（lint/tsc/test）保持全绿；分支 t-q07-style-prototypes，不合并 main（选定后按新基准统一入库）。
- 单套方向限 1 个 CSS 变量组（色板/字阶/圆角/阴影），屏间共享——体现「换 token 即换风格」。
