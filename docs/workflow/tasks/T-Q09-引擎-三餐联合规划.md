# T-Q09 引擎：一日三餐联合规划（L2）

> 立项：T-Q05 实施路线第 5 步首卡（确认书 v2 已生效 PD-024，2026-10-14 派发）。级别：**L2**。
> 目标：推荐引擎从「单餐组合（PD-018 MealRole 槽位）」升级为「次日早/中/晚三餐联合规划」——餐型维度 + 跨餐约束（必消跨餐分配/主蛋白不重复/菜系烹饪方式主食材不撞/儿童餐适配/已吃菜避开窗口），为契约+DB 卡（下一卡）提供稳定的三餐计划模型。

## 需求（引擎层，不碰 apps/ 与契约包）

1. **餐型维度**：新增 MealSlot（'breakfast'|'lunch'|'dinner'）与餐型菜品池概念——早餐从轻食池出菜（粥/饼/蛋/豆制品类， Dish 侧以既有的餐型/类别字段判定，无字段则在 types 增加可选 mealTypes 并兼容现数据）；午/晚餐走现有 MealRole 槽位组合（主菜+配菜+汤，道数随人数伸缩，缺槽留空如实标注 PD-018 沿用）。
2. **输入**：TonightContext 扩展为日计划上下文——成人/儿童人数（儿童>0 触发儿童餐约束）、必消食材（硬要求，可跨餐分配，全部必须用上）、临时忌口（当日生效，与长期硬禁忌同效但独立标注）、想吃的菜（选填；与忌口/必消冲突时如实标注未排入，不硬凑）、餐次勾选（早/中/晚任选，只出所选餐次）、已吃菜避开窗口（默认 7 天可调，菜品级聚合沿用 A3）。
3. **输出**：三餐联合计划——所选餐次各一套菜 + 每餐的 FilterTrace（沿用现有可解释口径）+ 跨餐约束落位说明（哪个必消分到了哪餐、哪个想吃未排入及原因）；同一输入确定性输出（稳定排序/哈希沿用）。
4. **跨餐约束**（新模块，建议 day-plan.ts）：①必消跨餐分配（可一道菜用掉多样必消；分配结果进 trace）；②一天内主蛋白不重复；③菜系/烹饪方式/主食材三餐不撞；④儿童>0 时全天菜品避辣/避刺多/避过硬（safety 层扩展属性过滤，属性缺失的菜不因此误杀——按现 DishView 可得字段判定，缺字段视为未知不硬拦）；⑤三餐总时长与「常做时长档」匹配（现有 feasibility 口径按餐应用）。
5. **调整语义**：换一道=同餐型候选替换（swap-candidates 按餐型过滤）；换一餐=该餐整体重推、其他餐不变且跨餐约束仍成立（重推失败保持原餐并给原因）；换一批=全天重推。
6. **空手**：任一所选餐次出不了 → 按餐如实说明（无菜型/时间型/组合冲突，PD-017+PD-014 口径扩展），给调整出路（放宽临时忌口/删必消/换想吃的菜）。
