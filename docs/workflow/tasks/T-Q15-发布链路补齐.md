> 立项：T-Q05 ④验收报告 §3 五项发布阻断。目标：把发布做成有备份、有迁移、有内容、有查库健康门禁、有回滚、有冒烟的一条链路；**本卡实施与预演阶段不改变生产运行版本**，最终发版另要产品负责人明确窗口与授权。

## 依据

## 需求

1. **备份**：新增 `tools/prod-backup.mjs`（`pnpm backup:prod`）。ssh 服务器、source `.env` 后 `docker run --rm -e DATABASE_URL postgres:18-alpine pg_dump --format=custom --no-owner --no-privileges` 写 `backups/family_menu-<ts>.dump` 并用 `pg_restore --list` 自检；manifest 记录当前 API 镜像 tag、VERSION、库大小；保留最近 5 份。不得打印 DATABASE_URL。`--dry-run` 只打印计划。
2. **部署内迁移+内容**：`tools/deploy-api.mjs` 顺序改为 备份 → pull → 新镜像一次性容器跑 `prisma migrate deploy` → `prisma db seed` → `check-safety.ts` → `up -d api` → `/health` 版本核对 → `/health/db` 要求 `db=connected`。任一步失败即停并保持旧容器；输出回滚命令。`--skip-migrate/--skip-content/--skip-backup` 仅演练用，必须显式传。
3. **回滚**：新增 `tools/rollback-api.mjs`（`pnpm rollback:api -- --to <tag>`）：校验服务器有该镜像 → `API_TAG=<tag> compose up -d api` → `/health` status ok；明确「迁移为加列式、旧镜像兼容新 schema；仅数据损坏才用备份 dump 恢复（L3 另行授权）」。支持 `--dry-run`。
4. **同窗口发布**：新增 `tools/deploy-release.mjs`（`pnpm deploy:release`）：预构建 H5 + 打 tar + scp 暂存 → 执行 deploy:api（慢步骤期间旧 H5 仍可用）→ 立即远端原位替换 H5（复用 deploy:h5 的备份/保 inode 例程）→ 生产冒烟 `tests/e2e/T-Q15-prod-smoke.mjs`（登录→首页→新契约 `/api/recommend` 200→`/health`；口令仅经环境变量）→ 服务器端精确清理冒烟 Plan → 打印摘要。API 切换至 H5 完成目标窗口 <60s；失败即停并给回滚命令。
5. **生产快照预演**：dump 生产库（只读）→ 恢复至生产机临时 `postgres:18` 容器（不发布端口、用后即删）→ 对新镜像跑 migrate deploy + seed + check:safety → 断言迁移全应用、PUBLISHED 菜 0 条 HARD 违规、早餐菜 ≥6、`_prisma_migrations` 无 failed。证据 `evidence/T-Q15/rehearsal.md`（不存 dump 本体）。
6. **文档**：OPS-LOG 加发布检查单（备份路径/镜像 tag/迁移数/冒烟结果/回滚 tag）；CURRENT 同步。main 分支保护需产品负责人到 GitHub Settings 开启（本机无 admin 凭据，主控不代办）。
