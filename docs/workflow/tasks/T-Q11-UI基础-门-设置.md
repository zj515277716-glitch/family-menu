## 需求

1. **登录门（S-01，T-A2 口径）**：口令输入 → API 校验 → 会话 token（不做多人账号/微信登录，单家庭口令即可）。未登录一律挡在门外；会话失效/401 由请求封装统一处理（跳回门页）。
2. **冷启动引导（S-02，C-8）**：判定「无家庭设置」时先引导填长期设置（偏好/忌口/厨具），完成才能进主流程；已填过则直达主流程。避开池为空属正常不阻断。
3. **统一请求封装**：超时、网络错误、401 一处处理（设计规则 6）。所有后续卡的 API 调用都走这层；本卡只搭封装与其覆盖的 auth/settings 调用。
4. **Tabbar 与路由框架**：3 个 Tab（首页/历史/设置）+ 子页与弹层的路由骨架。本卡只放设置页为真实页面；首页/历史/主流程各屏给空壳占位（标题 + 「下一卡实现」提示，不占真内容）。
5. **设置页（S-12，C-1）**：iOS 分组列表——成人/儿童人数步进、常做时长档（15/30/60）、家里有的锅（多选）、喜欢菜系（多选）、忌口（过敏=硬禁忌红色标注「推荐、清单、做法里都绝不会出现」/不吃=软偏好标注「有得选就不做，实在避不开会提前告诉你」）、已吃菜避开窗口（3/5/7 天，默认 7）。选中即高亮、保存后「已保存」、刷新/重进原样还在、保存失败提示「没保存上」保留已改值。
6. **token 主题落地**：apps/h5 全局样式引入 design-spec-v2 §1 的 token（色板/字阶/间距/圆角/阴影），NutUI 主题变量对齐。本卡范围内组件用 NutUI 组件 + 主题变量，不新增手写组件样式（设计规则 7）。
