> 状态：✅ 已定稿（2026-09-04，产品负责人确认通过，PD-011）。本文件与 `e-final.html` 共同构成本版 UI 唯一事实源。

> 依据：`docs/ui-redesign/style-options.md` §3.2.5（E tokens）、`PRODUCT-CONFIRMATION.md`（A 部分 PD-001~009）、DEC-007（图像规则）。

## 1. 设计关键词

**现代中式家庭**：朱砂红 × 宣纸米黄 × 墨黑文字。
有食欲、对比强、不冷淡；像一本干净的家常菜谱，而不是一个软件后台。

- 主色朱砂红只用于「可点击的关键动作」和「关键卡顶条」，不大面积铺。
- 页面底色是宣纸米黄，卡片比页面更亮一层，靠阴影和边框浮起来。
- 行高 1.65、字重 600（标题），读起来松弛、不紧绷。

### 2.3 卡片规则（E 方案的识别性所在）

- 卡片底 `#FFFCF5` 比页面底 `#FBF6EC` 亮一层。
- **关键卡顶条**：`--fm-card-accent-bar: 2px solid #C8392E`，加在页面里最重要的一张卡顶部。
- **每页至多 1 张关键卡**；普通卡片一律不加顶条（做法页：只有「做法」卡带条）。
- 换菜弹窗（sheet）自身带顶条，弹窗所在页不再另有顶条卡。

## 5. 文案原则（写 UI 文案时逐条对照）

1. **如实展示**：有多少写多少——候选「共 1 个/共 0 个」、历史「3 条记录」、没记录就画空态，不编数字。
2. **必消是硬要求**：说清「一定会用上；用不上的方案不会推荐」，做不到就给空手场景（s6），不凑数。
3. **不评判谁做饭**：反馈只说「用于以后推荐」，页面不出现谁做、做得好不好之类的评价语。
4. **禁止假成功**：没有任何「假装完成」的状态；错误必配一个解释和出口（s15 重试）。
5. **未连接必明说**：连不上服务就明说「服务未连接，暂时拿不到菜单」，绝不展示假菜单。
6. **人对人说话**：用「你/我们」短句，不用「加载失败 E-500」这类机器话。

## 6. 图像规则（DEC-007）

- 所有菜品图一律**试做实拍**：先把菜做出来拍照，再替换占位。
- 设计稿/开发阶段一律用「emoji + 试做实拍位角标」占位，**禁止**AI 生成菜品图、网图、插画替代。
- 占位尺寸：菜品卡 56×56（`.dish-img`）；做法页头图高 170（`.photo-ph`）。
