## 切片序列

### TP-01 运行与生产安全基线
- **范围**：本机建立真实 PostgreSQL 运行环境（替代"无 DB 空转"）；H5 未配置后端地址时改为明确提示"未连接服务"，**移除自动 Mock 兜底**；移除前端令牌硬编码；修复 H5 独立类型检查失败。
- **完成标志**：本机能从前端到真实数据库完整走通一次推荐→清单；公网暴露面收敛为单一家庭口令。
- **对应需求**：五、明确不做（假数据兜底）；PD-007 部署前置。

### TP-02 必消食材切片（核心输入真实生效）
- **范围**：中文名 → ingredientId 的稳定映射（建立食材别名/标准名机制）；推荐引擎将必消食材从加分项改为**硬过滤**（PD-001）；无方案可消耗时返回明确的空手原因文案。
- **完成标志**：输入"番茄"→ 推荐/不推荐的判定可被证据复现；空手场景文案按 PD-001 展示。
- **对应需求**：三、步骤 2；四、必须具备。

### TP-03 换菜切片（真实替换）
- **范围**：单菜换改为真实替换并持久化（同类型候选、带耗时/口味）；换菜原因改为选填（PD-003）；换菜后购物清单与备菜顺序联动重算。
- **完成标志**：换菜后界面、数据库、清单三者一致，证据可复现；杜绝"假成功"。
- **对应需求**：三、步骤 4。

### TP-04 购物清单切片
- **范围**：必消食材在清单中标记"已有"不删（PD-004）；按今晚人数自动缩放分量并取整（PD-005）；合并去重、按类别分组、常备调料不出现（回归既有能力）。
- **完成标志**：人数缩放与"已有"标记的数值证据可复现。
- **对应需求**：三、步骤 5。

### TP-05 反馈三问切片
- **范围**：反馈简化为三问（做了没/好吃一般翻车/下次还做），耗时选填（PD-006）；如实记录（本轮不做学习）。
- **完成标志**：三问提交后数据落库证据；旧五项表单移除。
- **对应需求**：三、步骤 6。

### TP-06 菜库扩充（流程验证之后）
- **范围**：用内容管线起草家常菜单（运行时零 LLM，产物只落 DRAFT），产品负责人确认后发布；目标先 10–12 套。
- **完成标志**：发布菜单数量证据；推荐在多套菜单下多样性可复现。
- **对应需求**：三、步骤 3（先跑通再扩）；六、以后再做中的内容部分。

### TP-07 公网部署
- **范围**：云服务器部署 + 域名/备案 + HTTPS + 口令保护；回滚预案。
- **打断点**：购买服务器/域名/备案属"账号、费用或外部平台操作"，届时单独问产品负责人一次。
- **完成标志**：公网 URL 可用证据 + 冒烟清单全绿。
- **对应需求**：八、使用场景与部署（PD-007）。

### TP-08 真实用一周（UAT）
- **范围**：产品负责人按主流程真实使用一周；每日决策耗时、忌口事故、必消食材消耗率记录。
- **完成标志**：成功标准（七）逐条达成或记录未达成原因。
- **对应需求**：七、成功标准。
