# 5 页面线框图（Wireframes）

> 产物归属：UI/UX 设计 Agent｜对齐实施方案「环节 2.5 UI/交互设计」
> 设计依据：shared v0.1 契约（family/dish/menu/plan/api）+ engine View 类型 + list-merger ShoppingList
> 组件库：`@nutui/nutui-react-taro` 4.x（编译目标 H5，微信内打开）
> 移动端竖屏，逻辑宽度 375px；ASCII 框宽约 42 字符示意，非像素精确。
> 视觉定稿=人工决策点（见 theme-tokens.ts 候选方案），本文件仅定结构与组件。

## 0. 全局导航结构（TabBar + 流式页）

底部 TabBar 3 个常驻入口，保证主流程「2 分钟定今晚」最短路径，且任意 Tab 无死胡同：

```
+----------------------------------------------------------+
|  内容区（当前页面）                                        |
+----------------------------------------------------------+
|  [今晚]      |     [历史]      |     [设置]              |
|  /pages/tonight  /pages/history   /pages/setup            |
+----------------------------------------------------------+
```

| 页面 | 路由 | 类型 | 进入方式 |
|---|---|---|---|
| 今晚情境（F2） | /pages/tonight | Tab（首页） | App 启动 / 点击 Tab |
| 历史与反馈（F6/F7） | /pages/history | Tab | 点击 Tab |
| 家庭规则设置（F1） | /pages/setup | Tab | 点击 Tab（首次启动强制进入） |
| 三套候选（F3） | /pages/candidates | 流式页 | 今晚页点「推荐」 |
| 采购清单+备菜（F4/F5） | /pages/plan | 流式页 | 候选页「选定此套」锁定后 |

- 首次启动检测：`FamilyRule` 未设置 -> 强制跳 `/pages/setup`，完成保存后回 `/pages/tonight`。
- 流式页（candidates/plan）顶部 `NavBar` 带返回箭头，返回不丢已填情境（tonight 状态保留在 Zustand）。

## 页面 1：家庭规则设置（F1）

- 路由：`/pages/setup`
- 功能：人数 / 绝对禁忌 / 常用时长 / 器具 / 偏好菜系，首次设置 ≤90 秒
- 数据写入：`PUT /api/family/rules`（`FamilyRule`）+ 禁忌 `ExclusionRule[]`（scope=INGREDIENT|DISH|TAG，severity=HARD|SOFT）

```
+--------------------------------------------+
| [<返回]   家庭规则设置          [NutUI:NavBar] |
+--------------------------------------------+
|                                            |
|  默认人数                                   |
|  [  -  ]  [  4  ]  [  +  ]   [NutUI:Stepper]|
|  数据: FamilyRule.defaultPeople             |
|                                            |
|  常用时长（可多选）            [NutUI:Checkbox.Group]|
|  [x]15分钟  [x]30分钟  [ ]60分钟            |
|  数据: FamilyRule.timeBudgets ⊂ [15,30,60]  |
|                                            |
|  厨房器具（可多选）            [NutUI:Checkbox.Group]|
|  [x]炒锅    [x]电饭煲                       |
|  [ ]蒸锅    [ ]空气炸锅                     |
|  数据: FamilyRule.equipment ⊂ EQUIPMENT     |
|  (wok/rice_cooker/steamer/air_fryer)        |
|                                            |
|  偏好菜系                      [NutUI:Tag]+ |
|  [湘菜 x][家常 x][清淡 +]                   |
|  数据: FamilyRule.cuisines[]                |
|                                            |
+--------------------------------------------+
|  禁忌设置（绝对禁忌/不喜欢）   [NutUI:Cell]  |
|  > 食材禁忌（3项）             [NutUI:Badge] |
|  > 菜品禁忌（1项）                          |
|  > 标签禁忌（如"内脏"）                     |
+--------------------------------------------+
|  禁忌编辑面板（Popup 弹层）   [NutUI:Popup]  |
|  ┌──────────────────────────────────────┐  |
|  │ 搜索食材/菜品           [NutUI:Search]│  |
|  │ [番茄] [鸡蛋] [腊肉] ...              │  |
|  │ 选中：番茄                             │  |
|  │ 严重度 [硬禁忌][软禁忌] [NutUI:Radio] │  |
|  │   HARD=过敏/绝对(安全过滤一票否决)     │  |
|  │   SOFT=不喜欢(降权不阻断)             │  |
|  │ 备注：爸爸不吃            [NutUI:Input]│  |
|  │             [取消]  [添加] [NutUI:Btn]│  |
|  └──────────────────────────────────────┘  |
|  数据: ExclusionRule{scope,targetId/Tag,    |
|        severity,note}                       |
+--------------------------------------------+
|                                            |
|  [        保存规则         ]  [NutUI:Button]|
|  type=primary, block；保存后回 /pages/tonight|
+--------------------------------------------+
```

设计要点：
- 单页可滚动表单，所有字段默认值预填（defaultPeople=4），首次 90 秒内可只填「人数+时长+器具」即可保存，禁忌/菜系可后补。
- 禁忌用二级 Cell+Popup，避免主表单过长；HARD/SOFT 用 Radio 强制二选一（对应 SeveritySchema）。
- 作用域（INGREDIENT/DISH/TAG）由所选分类自动决定，用户无需感知枚举值。

## 页面 2：今晚情境输入（F2）

- 路由：`/pages/tonight`（首页 Tab）
- 功能：人数、时间档（15/30/60 三选一）、最多 3 个必须消耗食材
- 数据产出：`PlanContext{people, timeBudgetMin:15|30|60, mustUse:string[]}` -> `POST /api/recommend`

```
+--------------------------------------------+
|  今晚吃什么                  [NutUI:NavBar]  |
+--------------------------------------------+
|                                            |
|  ┌──────────────────────────────────────┐  |
|  │   [装饰插画:今晚吃什么]               │  |
|  │   asset-tonight-hero（见 assets-spec）│  |
|  └──────────────────────────────────────┘  |
|                                            |
|  几个人吃？                                 |
|  [  -  ]  [  4  ]  [  +  ]   [NutUI:Stepper]|
|  默认=FamilyRule.defaultPeople              |
|                                            |
|  今晚有多少时间？            [NutUI:Radio.Group]|
|  ( )15分钟  (x)30分钟  ( )60分钟            |
|  默认选 FamilyRule.timeBudgets[0]           |
|  数据: PlanContext.timeBudgetMin ∈[15,30,60]|
|                                            |
|  冰箱里必须消耗的？(最多3个)                 |
|  [🔍 搜索食材 ]               [NutUI:Search] |
|  选中：                                      |
|  [番茄 x] [五花肉 x] [+ 最多3个] [NutUI:Tag]|
|  数据: PlanContext.mustUse[]（≤3）          |
|  选中达3个后 Search 置灰禁用                 |
|                                            |
+--------------------------------------------+
|                                            |
|  [      推荐今晚吃什么      ]  [NutUI:Button]|
|  type=primary, block                        |
|  -> POST /api/recommend -> /pages/candidates|
+--------------------------------------------+
|                                            |
|  [今晚]      |     [历史]      |     [设置]  |
|  [NutUI:Tabbar][NutUI:Tabbar.Item x3]      |
+--------------------------------------------+
```

设计要点：
- 三个输入全部预填默认值，可直接点「推荐」（满足 2 分钟主流程，无强制必填卡死）。
- mustUse 上限 3 个用 Tag 计数 + Search 禁用强约束，超限时不可继续加（契约 ≤3）。
- 时间档用 Radio 单选（三选一，区别于 F1 的多选时长）。

## 页面 3：三套菜单候选（F3）

- 路由：`/pages/candidates`（流式页，NavBar 带返回）
- 功能：每套显示总耗时、难度、主食材、推荐理由；整套换/单菜换（记录原因）
- 数据：`POST /api/recommend` 返回 `RecommendResponse{candidates: ScoredMenu[]}`，每条 `ScoredMenu{menuId,score,reasons[],breakdown}`；join `MenuView{name,scene,totalActiveMinutes,dishes}` + `DishView{name,mealRole,cuisine,flavorTags,spicyLevel,activeMinutes,equipment}`

```
|  ┌──────────────────────────────────────┐  |

|                                            |
|  (纵向滑动浏览 3 套)                        |
+--------------------------------------------+
|  [     选定此套（锁定）     ]  [NutUI:Button]|

|  -> POST /plans/:id/lock -> /pages/plan     |
+--------------------------------------------+
```

单菜换面板（ActionSheet / Popup）：

```
+--------------------------------------------+
|  换菜：番茄牛腩           [NutUI:ActionSheet]|
+--------------------------------------------+
|  换成（同角色候选 3 道）：                   |
|  > 咖喱牛腩   [主菜] 28分钟  微辣            |
|  > 土豆烧牛肉 [主菜] 35分钟  咸鲜            |
|  > 番茄炖牛腱 [主菜] 30分钟  酸甜            |
+--------------------------------------------+
|  原因（必填，记录用于学习）   [NutUI:TextArea]|
|  [ 太麻烦 ] [ 食材不够 ] [ 不喜欢 ] [其他]   |
|  快捷原因 Tag + 自由输入                     |
+--------------------------------------------+
|  数据: POST /plans/:id/swap                 |
|   {swapType:'单菜换', dishId, reason}       |
|  -> EventType.SWAP_DISH                    |
+--------------------------------------------+
```

设计要点：
- 3 张卡纵向滑动，第一张默认为推荐（score 最高），顶部标「推荐」徽标。
- 「整套换」对当前候选调用 swap（swapType=全换，记 reason），返回新候选替换该卡。
- 「单菜换」弹 ActionSheet，只列同 mealRole 候选，reason 必填（快捷 Tag 降低输入成本，事件留痕用于推荐学习）。
- 「选定此套」作用于「当前滚动到/最后操作」的卡 -> 锁定（status: PROPOSED->LOCKED）-> 跳清单页。
- 推荐理由 reasons[] 直接展示给用户（可解释性，对应 ScoredMenu.reasons）。

异常态（见 interaction-flow.md）：
- 候选不足 3 套：如实展示，不足位置不补占位，顶部 Cell 提示「候选较少，可调整情境或去设置补充菜库」。
- 0 套候选：Empty 组件 + 「去设置检查禁忌/调整情境」按钮，无死胡同。

```
+--------------------------------------------+
|  [   做完了，去反馈   ]      [NutUI:Button]  |
```

设计要点：
- Tabs 切换「清单 / 备菜」两视图，同页承载 F4+F5，避免跳页。
- 清单按 `CATEGORIES` 固定顺序分组（蔬菜/肉类/水产/蛋奶/调料/主食），空分组隐藏；常备调料已由 list-merger 去除，无需用户勾掉盐/酱油。
- 备菜 Timeline 直接渲染 `Menu.prepSequence`，标注并行节点（parallel=true），强调「并行工序后真实总工时」。
- 勾选即时 PATCH 持久化，刷新不丢勾选状态。
- 底部「去反馈」承接 F6 主入口（烹饪后回填结果）。

## 页面 5：反馈 + 历史（F6 + F7）

- 路由：`/pages/history`（Tab）
- 功能：极简反馈（锁定/做了/没做/下次还做）；成功菜单一键复用
- 数据：`CookLog{cookedAt,actualMinutes,result:success|partial|fail,failPoints?,willRepeat?}` + `Event{type:COOKED|NOT_COOKED|REPEAT}` + `Plan{planDate,status}`；历史 `GET /plans`

空状态（首次使用，无任何历史/计划）：

```
+--------------------------------------------+
|  历史与反馈                   [NutUI:NavBar] |
+--------------------------------------------+
|                                            |
|  ┌──────────────────────────────────────┐  |
|  │       [空状态插画]                     │  |
|  │  asset-history-empty（见 assets-spec） │  |
|  │      一只空盘子和一双筷子              │  |
|  │       旁边一个问号气泡                 │  |
|  └──────────────────────────────────────┘  |
|                                            |
|          还没有做饭记录                      |
|      [  定今晚吃什么  ]    [NutUI:Button]   |
|      -> /pages/tonight                      |
|                                            |
+--------------------------------------------+
```

设计要点：
- 顶部「今日计划状态条」承接当日 Plan 状态流转：PROPOSED->LOCKED->COOKED（「开始烹饪」可改为「已完成」，点后展开反馈表单）。
- 反馈表单极简：做了/没做二选一；做了才展开实际耗时+结果+失败原因+下次还做；没做只记原因（result=not_cooked，Event.type=NOT_COOKED）。
- 「下次还做」即 result=repeat 时同步 Event.type=REPEAT，且该菜单进入「一键复用」高亮（历史列表 [复做] 按钮 -> POST /plans/:id/repeat 直接生成新 Plan 回 tonight）。
- 历史列表每条显示日期/菜单名/结果色标（成功绿/部分橙/未做灰），复做按钮常驻。

## 跨页面交互备注

1. 状态保持：tonight 填写的情境在跳 candidates 后返回不丢（Zustand 全局 store）；candidates 选定锁定后 plan 页数据来自该 Plan 快照。
