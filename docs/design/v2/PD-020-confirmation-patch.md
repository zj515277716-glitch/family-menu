# PD-020 确认书修订草案（一日三餐规划）

> 状态：**待产品负责人确认**（确认前 PRODUCT-CONFIRMATION.md 现行版本仍有效）
> 起草：主控，2026-10-08｜依据：PD-020 决定（5/5 拍板）｜本草案将整体替换 PRODUCT-CONFIRMATION.md 的 A 部分与 C 部分相关条款；B 部分（UI）随 PD-019 新基准另行替换。

## A 部分修订（需求确认）

### §一、产品定位（改写）
- **产品一句话**：晚上 10 分钟定好明天一家人的早中晚三餐，顺手给出一次性采购清单和备菜建议。
- **目标用户**：产品负责人自己一个家庭（家庭主理人）。单家庭使用，不做多人账号。

### §二、要解决的核心问题（改写）
1. 每天三顿「吃什么」的决策疲劳（不止晚餐）；
2. 一家人喜好/忌口/营养要兼顾，搭配费心；
3. 买菜凭感觉，容易买重买漏、买不全；
4. 冰箱食材想消耗，不知道能做什么。

### §三、主流程（第一阶段唯一旅程）与已确认决定（重写）

| 步骤 | 已确认的产品决定 |
|---|---|
| 1. 设置家庭与忌口 | 人数/厨具/菜系/忌口，设一次长期生效；**硬禁忌一票否决，绝不推荐** |
| 2. 晚上定明天的餐 | 首页「定明天的餐」：选**成人/儿童人数**、**必消食材**（硬要求，PD-001 口径沿用）、**临时忌口**（当日生效，如生病不吃牛肉/虾）、**想吃的菜**（选填）、**餐次勾选**（早/中/晚任选，默认全选） |
| 3. 推荐菜谱 | **一键生成次日三餐**：早餐/中餐/晚餐各一套；综合偏好、忌口、必消、想吃的菜、**当天已吃的菜避开**（窗口可调，默认 7 天）、**营养搭配**、**三餐多样性**；儿童餐**少辣/少刺/软烂** |
| 3a. 调整（可选） | 某餐某菜「换一道」（同餐型候选，原因可填可不填）；某餐整套「换一餐」（该餐重推，不动其他餐）；全部「换一批」；**换了就是真的换了** |
| 4. 确认三餐 → 采购清单 | 三餐食材**合并去重、一次买齐**；按（成人+儿童）人数**自动换算凑整**；必消标"已有"不删（PD-004 沿用）；常备调料不出现 |
| 5. 备菜建议 | 分「今晚预处理」（泡/腌/解冻）与「明早先做」（早餐工序前置），按三餐时间轴排 |
| 6. 次日执行与记录 | 当天打开看当天三餐，点菜看做法；**做完某一餐可单独「记一笔」**（做了没/好吃吗/下次还做，耗时选填）；**评价可选、按餐独立、漏评不追**；评价进推荐依据 |

### §四、必须具备（做不到不算完成）
- 忌口零事故：硬禁忌的食材/菜绝不出现在任何一餐的推荐里；
- 必消食材真实生效：输入的东西真实影响推荐，没消耗会明说；
- 换菜真实生效：换一道/换一餐/换一批都是换了就是换了，禁止假动作；
- 采购清单准确：三餐合并 + 标已有 + 按人数缩放 + 去重 + 常备调料不出现；
- 反馈如实记录（按餐）；
- 极简做法页：点当天任一餐的任一道菜，看用料（按人数缩放）与分步做法；
- 三餐营养与多样性：一天三餐主蛋白/菜系/烹饪方式不重复（引擎约束，可见效果可解释）；
- 儿童餐适配：儿童人数 >0 时，菜品选择避开辣/刺多/过硬（引擎约束）。

### §五、本版明确不做
多人账号/微信登录、**早餐外的饮品加餐零食**（只管早中晚三正餐）、家庭投票、库存管理、拍照识别、社区分享、语音交互、运行时 AI、演示假数据自动兜底（改为明确提示"未连接服务"）、精确营养数值计算（只做结构性搭配约束，不做热量/营养素克数计算）。

### §六、从"本轮"移到"以后再做"
精确营养计算（热量/营养素）、饮品加餐零食、做法页视频、库存管理。

### §七、成功标准
真实用一周——每天晚上定明天三餐 ≤ 10 分钟；忌口零事故；输入的必消食材都被真正用上；一家人觉得「搭配得不重样、吃得舒服」。

## C 部分修订（功能行为与验收，六问条款重写）

> 沿用总原则（真实数据、所见即所得、失败明说）不变；屏号引用随 PD-019 新基准文档落地后统一改指向。以下条款按新流程重写，编号沿用 C-x 体系以便对账。

### C-1 长期设置（设置 Tab）
- **场景**：第一次使用，或家里情况变了（人数、锅、忌口等）。
- **操作**：设置 Tab → 改默认成人/儿童人数、常做时长档、家里有的锅、喜欢的菜系、忌口（过敏=硬禁忌 / 不吃=软偏好）、**「已吃菜避开窗口」**（3/5/7 天，默认 7 天）→ 保存。
- **应该看到**：选中即高亮；保存后「已保存」；硬禁忌红色标注「推荐、清单、做法里都绝不会出现」，软偏好标注「有得选就不做，实在避不开会提前告诉你」。
- **保存**：是，长期默认。
- **刷新/重进**：设置原样还在；换设备一致。
- **失败恢复**：保存失败提示「没保存上」，保留已改值可再点。

### C-2 定明天的餐（首页下半区）
- **场景**：每天晚上，定明天一家人吃什么。
- **操作**：首页「定明天的餐」→ 改成人/儿童人数（默认带出长期设置）、填必消食材（标签）、选临时忌口（今日生效）、填想吃的菜（选填）、勾选餐次（早/中/晚，默认全选）。
- **应该看到**：人数分成人/儿童两组步进；必消以标签列出；临时忌口独立区（标注「仅明天生效」，区别于长期硬禁忌）；餐次勾选状态清晰。
- **保存**：是，属「明天计划」的临时设置，与长期设置分开。
- **刷新/重进**：同一次编辑会话内重进，已填内容不丢（任何操作顺序不丢，设计规则 5）。
- **失败恢复**：保存失败提示重试，不丢已输入。

### C-3 推荐菜谱（设置 → 三餐菜单）
- **场景**：明天的餐填好，准备生成。
- **操作**：点「推荐菜谱」。
- **应该看到**：先骨架屏「正在为明天搭配三餐…」；随后进入三餐菜单页：**早餐/中餐/晚餐**分区展示，每餐按人数+餐型出菜（早餐轻食、午晚正餐；道数随人数伸缩，沿用 PD-018 缺槽留空如实标注不凑数）；顶部横幅「✓ 必消食材已用上：番茄、鸡蛋」（未消耗则如实标注）；**想吃的菜若与忌口/必消冲突，如实说明「想吃的 X 与忌口冲突，未排入」**（补充方面①）。**推荐必须用上全部必消、不违反任何硬禁忌与临时忌口、总时长匹配**。
- **保存**：是。明天三餐保存，当晚内不随机变化。
- **刷新/重进**：同一天重进看到同一份三餐（不重新生成）。
- **失败恢复**：加载失败 →「⚠ 服务未连接」+「重试」，绝不显示假菜单。

### C-3a 调整三餐（换一道/换一餐/换一批）
- **场景**：对某餐某菜或某餐整套不满意。
- **操作**：某菜「换一道」（弹同餐型候选，原因可填可不填）/ 某餐「换一餐」（该餐整体重推，其他两餐不动）/「全部换一批」（三餐重推）。
- **应该看到**：按钮加载态后真的替换；换后必消横幅、采购清单、总时长同步更新；新一套仍须用上全部必消、不违反忌口、儿童餐仍适配。
- **保存**：是，明天三餐更新。
- **刷新/重进**：看到最后换出的版本。
- **失败恢复**：换失败提示「没换成」，原菜单保持可再试。

### C-4 明日采购清单与备菜建议
- **场景**：三餐确认，准备买明天的菜。
- **操作**：三餐菜单页点「查看采购清单」。
- **应该看到**：三餐食材**合并去重**一张清单；按（成人+儿童）人数换算凑整；必消标「已有」不删；常备调料不出现；「就按这个买」勾选；**备菜建议**分「今晚预处理」（泡/腌/解冻）与「明早先做」（早餐工序前置）。
- **保存**：是。勾选与清单随计划保存。
- **刷新/重进**：勾选状态还在。
- **失败恢复**：保存失败提示，保留已勾选。

### C-5 当天执行：看做法 + 按餐记录（首页上半区）
- **场景**：第二天，照着做今天三餐。
- **操作**：首页上半区显示**今天三餐**（按当前时间把「下一餐」置顶：早 6-10 点早餐在前，过 10 点中餐在前，依此类推）；点某道菜看做法；做完某一餐点「记一笔」。
- **应该看到**：做法页沉浸大图 + 用料（按人数缩放）+ 分步做法（沿用 PD-016 方向 A）；「记一笔」**只针对这一餐**：做了没 → 好吃/一般/翻车 → 下次还做吗 → 耗时选填；**评价可选，漏评不弹窗不追**；三餐各自独立记录。
- **保存**：是。每餐评价独立落库，进推荐依据（好评加权）。
- **刷新/重进**：已记录的餐显示评价标签；未记录的餐正常可记。
- **失败恢复**：提交失败提示「没保存上」，可重提（同日同餐重提覆盖）。

### C-6 历史
- **场景**：回看过去吃过的三餐。
- **操作**：历史 Tab → 按日查看过去的早/中/晚三餐与每餐评价标签。
- **应该看到**：按日分组，每天展开三餐；每餐四色结果标签；点菜品可复看做法。
- **保存**：只读。
- **刷新/重进**：内容一致。
- **失败恢复**：连不上服务 →「服务未连接」横幅 + 重试。

### C-7 空手场景（无一餐能出）
- **场景**：必消/忌口/想吃的菜凑不出任何一餐。
- **应该看到**：如实说明是哪一餐、因为什么出不了（无菜型/时间型/组合冲突，沿用 PD-017 两型 + PD-014 组合口径扩展）；给调整出路（放宽临时忌口/删必消/换想吃的菜）。
- 其余同 C-3 失败恢复。

### C-8 冷启动（首次使用）
- **场景**：第一次打开，没有任何历史。
- **应该看到**：引导先填长期设置（偏好/忌口/厨具）→ 引擎无历史也能出餐（仅靠长期设置+当日情境）；「已吃菜避开池」为空属正常，不影响出餐。
