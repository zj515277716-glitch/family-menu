## 一、组件库选型（先定「用什么搭」，再定「长什么样」）

### 1. 你在买菜平台选 TDesign——家庭菜谱这边的对应事实（已核实）

TDesign 全家桶里**确有** React 移动端版：**`tdesign-mobile-react`**（[npm](https://www.npmjs.com/package/tdesign-mobile-react)，React 18.x + mobile web，官方文档 [tdesign.tencent.com/mobile-react](https://tdesign.tencent.com/mobile-react)）。它与小程序版 `tdesign-miniprogram` 是**两套独立实现**，视觉语言一致但代码不通用——所以不能直接套小程序版，但可以用它对应的 React web 版。

**关键风险（务必知悉）**：
- **成熟度存疑**：npm 最新版 0.18.0（0.x 未达 1.0），周下载量仅 ~387（作为对比，现用 NutUI 系列在万级）；API 仍可能 breaking change。
- **Taro 适配是最大变量**（见下第 4 条，对所有非 Taro 原生库同理）。

### 2. 候选对比（React 移动端，已核实现状）

| 候选 | 成熟度 | Taro 兼容性 | 与"整洁清新+统一排版"契合 | 风险 |
|---|---|---|---|---|
| **A. 沿用 NutUI 4 beta**（现状） | 中（beta 但生态最贴 Taro） | ✅ 唯一官方适配 Taro 4 的 React 库（`nutui-react-taro`） | 主题 token 体系完整（--nutui-* cssVars），现状问题在排版而非库 | 低（零迁移） |
| **B. tdesign-mobile-react** | ⚠ 低（0.x，周下载 ~387） | ❓ 需自测适配（Taro 渲染 `<View>` 抽象层，非原生 DOM 组件库普遍需验证） | 设计体系严谨、克制、现代（与偏好①②契合） | **高**：成熟度 + Taro 适配未知 + 全部页面重写 |
| **C. react-vant** | 中（有赞 vant 的 React 移植，社区活跃） | ❓ 同 B 需验证 | 视觉清爽但与 vant 小程序生态绑定，React 版关注度中等 | 中高（Taro 适配 + 全部重写） |
| **D. antd-mobile** | 中高（阿里系，历史悠久） | ❓ 同 B 需验证 | 偏企业工具感，"温馨家庭"调性需大量定制 | 中高（Taro 适配 + 视觉定制量大） |

### 3. Taro 兼容性说明（为什么这是决定性变量）

项目技术栈 = Taro 4 + React，编译目标 H5。Taro 的 React 组件渲染的是**Taro 抽象组件（`<View>/<Text>` 等）**，不是原生 HTML DOM。`tdesign-mobile-react` / `react-vant` / `antd-mobile` 都是**面向原生 DOM 的 web 库**，在 Taro H5 下能否正常工作**没有官方保证**——Taro H5 理论上最终也输出 DOM，但样式注入、事件代理、portal（弹层类组件）等边界处常出问题，需要实测。NutUI 是唯一**官方为 Taro 出专属包**（`nutui-react-taro`）的库，这是当初选它的原因。

### 4. 迁移成本与风险评估

| 方案 | 页面重写量 | Taro 适配验证 | 回退成本 | 综合风险 |
|---|---|---|---|---|
| 沿用 NutUI（仅换 token + 排版重构） | 0（只改 cssVars 与零散样式） | 无需 | 低 | **低** |
| 换 tdesign-mobile-react | 8 个页面全部重写 | 需先立探针卡实测（约半页卡） | 高（页面已重写则回不去） | **高** |
| 换 react-vant / antd-mobile | 8 个页面全部重写 | 同上需探针 | 高 | 高 |

### 5. 我的推荐（产品含义请拍板）

**推荐：沿用 NutUI 4，但把「排版差」当作排版问题修——而不是换库**。
理由：① 你的三条「不喜欢」（杂乱、偏冷、卡通、呆板）和三条「一定要有」（步骤清晰、统一排版、风格统一）**全部是排版/视觉语言问题，不是组件库能力问题**——现有诊断（style-options.md §0.2：字号零散、间距无规律、卡片层级弱）也指向排版而非库；② NutUI 主题 token 体系完整，新视觉基准完全可以靠重写 token + 统一排版规则达成，**零迁移成本、零新风险**；③ 换 tdesign-mobile-react 的收益（设计语言）与你的偏好并不冲突，但它 0.x 成熟度 + Taro 适配未知的组合，对「自用稳定工具」是**用确定的高成本换不确定的观感提升**。

**如果你确实被 TDesign 的视觉语言吸引**（比如买菜平台用得很顺手），我可以先立一张小探针卡：把 `tdesign-mobile-react` 拉进一个隔离页面实测 Taro H5 兼容性，成本约半天，实测绿再谈整体迁移——这是把「未核实」变成「已核实」的低成本路径。**默认按推荐走（沿用 NutUI），除非你明确要探针**。

## 二、视觉风格方向（候选，等你选一套）

基于你的偏好（清新整洁 + 中式有食欲 + 不冷、不卡通），从既有的 D/E/F 候选（style-options.md）按偏好筛选 + 修订，给 3 套方向。**注意：这只是方向，色值以最终定稿的 design-spec 为准。**

| 维度 | 方向① **暖白极简**（新推） | 方向② 和风暖木（D 修订） | 方向③ 青瓷清新（F 修订） |
|---|---|---|---|
| 风格语言 | 米白底 + 深棕字 + 低饱和暖橙点缀，大留白、强分区 | 日系木质温暖，克制留白 | 明亮青绿，年轻通透 |
| 主色 | `#C8541F` 暖陶橙（比现朱砂更柔、比暖橙更沉） | `#B07D4E` 暖木褐 | `#4A9D8F` 青瓷绿 |
| 与你偏好契合 | 整洁✓ 分区明确✓ 食欲感中✓ 不冷不卡通✓ | 整洁✓ 温馨✓ 食欲感中 | 整洁✓ 但偏冷（偏好表明确不喜欢冷）⚠ |
| 长辈友好 | 强（高对比、大留白） | 中（字色偏浅） | 中（冷调辨识度一般） |
| 与中式家常菜实拍图协调 | 好（暖底衬食） | 好 | 弱（冷底，红菜突兀） |
| 与 v1「番茄暖橙 #FF6B35」延续性 | 同源同系，迁移自然 | 中 | 差异最大 |

**推荐方向① 暖白极简**：把你喜欢的「整洁清新」和你不喜欢的「偏冷」同时满足——用暖色系做极简，分区靠留白+细线而非色块；食欲感靠暖橙点缀与实拍图，不靠大面积重色。**方向③因偏好表明确「颜色偏冷、不太适合中式餐饮」建议降权**。
