## 一、信息架构总览

```
登录（pages/login，进门一次口令，免登录设备自动进首页）
└── 底部 3 个常驻 Tab（NutUI Tabbar，reLaunch 切换清栈）
    ├── Tab1 今晚（pages/tonight）──默认落地页
    ├── Tab2 历史（pages/history）
    └── Tab3 设置（pages/setup）

Tab1 今晚 内嵌 4 个流式子页（navigateTo 推入、navigateBack 返回，不占 Tab 位）：
    ├── 候选套餐（pages/candidates）——推荐结果三选一 + 整套换「换一批」
    ├── 今晚计划（pages/plan）——锁定的菜单 + 购物清单 + 备菜顺序
    ├── 菜品做法（pages/dish）——用料 + 分步做法（点菜单卡进入）
    └── 反馈（pages/feedback）——三问极简：做了没/好吃吗/下次还做
```

## 二、3 个 Tab 各放什么（「我的东西在哪」速查）

### Tab1 今晚（默认页）— 「今天的事全在这」
| 内容 | 位置 | 说明 |
|---|---|---|
| 今晚人数/时长档 | 今晚主页（tonight） | 默认带出长期设置的值，属「今晚临时设置」 |
| 必消食材输入 | 今晚主页 | 输入框 + 标签，点推荐自动收进未确认文字 |
| 「推荐今晚吃什么」主按钮 | 今晚主页 | 2 分钟主流程入口 |
| 候选套餐三选一 | 候选页（candidates） | 每套 = 主菜+配菜+汤；「换一道」换单菜、「换一批」整套换 |
| 「就吃这套」锁定 | 候选页 | 锁定后进入今晚计划 |
| 购物清单 | 计划页（plan） | 标已有/人数换算/类别分组；「就按这个买」勾选 |
| 备菜顺序 | 计划页（plan） | 时间轴（先泡/先腌等） |
| 某道菜做法 | 做法页（dish） | 点菜单卡进入，沉浸大图 + 用料 + 分步 |
| 今天吃完了记一笔 | 反馈页（feedback） | 做完饭三问 |

### Tab2 历史 — 「过去吃过的都在这」
| 内容 | 位置 | 说明 |
|---|---|---|
| 按日查看过去菜单 | 历史主页（history） | 四色结果标签（做了好吃/一般/翻车/没做） |
| 历史某次的反馈详情 | 历史页内（现行实现） | 看耗时与评价 |
| 历史做法复看 | 历史 → 点菜品 → 做法页 | 复用做法页 |

### Tab3 设置 — 「长期生效的东西在这」
| 内容 | 位置 | 说明 |
|---|---|---|
| 默认人数/常做时长档 | 设置主页（setup） | 设一次长期生效 |
| 家里有的锅/厨具 | 设置主页 | 影响推荐可行性 |
| 喜欢的菜系 | 设置主页 | 偏好加权 |
| 忌口（硬禁忌/软偏好） | 设置主页 | 硬禁忌一票否决；显示「推荐/清单/做法绝不出现」红线提示 |

## 四、需要你确认的 3 个点

1. **Tab 结构与归属**：3 个 Tab 的内容分配如上（今晚=当天事务、历史=过往、设置=长期），是否符合直觉？尤其：购物清单/备菜顺序放在「今晚计划页」（Tab1 的子页）而非独立 Tab——你买菜的场景是直接进 Tab1 往下翻，还是更希望「清单」能一眼直达？
2. **「换一道」的入口位置**：现行在候选页每张菜卡上（C-5 已定），是否在计划页也要保留入口（看做法时顺手想换）？
3. 历史页的「复做」功能：确认书第六章列为「移到以后再做」，现行代码已实现历史复做（interaction-flow.md §2 步骤11）。**以哪个为准**？（这影响导航图是否画出该入口——建议按确认书「以后再做」不画，原型不呈现；如你要保留请告诉我）
