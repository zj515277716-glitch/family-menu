# family-menu 项目规则（对本工作区所有智能体生效）

本仓库是"家庭晚餐规划工具（个人自用版）"，按 `docs/plan/实施方案.md` 运转，采用四件套对齐机制：AGENTS.md / STATUS.md / DECISIONS.md / 开发日志.md。

## 全员纪律

1. 开工前必读：STATUS.md「当前任务卡」+ AGENTS.md；仓库文件与测试结果**优先于聊天上下文**（DEC-004）
2. 只做当前任务卡内的事；卡外发现问题→写进完成报告，不顺手修改（越界即拒收）
3. WIP=1：任何时刻只有一个活动代码任务（DEC-003）
4. 运行时代码禁止调用任何LLM API（DEC-006）
5. 禁止引入：Redis / 消息队列 / 微服务拆分 / K8s（DEC-008）
6. 测试必须真实执行：可复制命令+退出码+数字结果，禁止Mock冒充真实环境
7. 每个任务结束必须追加开发日志（五段式：START/DEV/TEST/REVIEW/COMPLETE）；未记录不得开始下一任务
8. 每STEP完成后状态停"待用户审核"，用户批准前不合并、不启动下一STEP（DEC-005）
9. 缺信息→停下来问队长，不脑补（"不知道就问，别猜"）

## 队长（SOLO Coder）专属纪律

- 只派发、收敛、维护四件套；**不亲自编写业务代码、不做技术决策**（技术争议→派发fm-arch出方案→抛用户）
- 派发指令必含5要素：目标 / AC / 输入资源 / 边界约束 / 异常升级路径
- 单任务打回上限3次；跨Agent ping-pong上限1次，超限自己介入重新定义问题
- 只认成员的 [✓]/[✗] AC自检，不认定性描述

## 引导例外

若四件套尚未建立（仓库刚初始化），唯一允许执行的任务是 STEP-00 协作框架初始化——此时队长可亲自创建文档文件（仅限文档，不含业务代码）。
