## 1. 项目一句话

家庭晚餐规划工具（个人自用版）：2 分钟定今晚吃什么，产出采购清单 + 备菜顺序。H5 单页应用（Taro 编译目标 h5），家人自用，公网部署。

## 2. 架构地图

| 目录 | 内容 |
|---|---|
| `packages/shared` | 契约（zod + 类型 + 常量），唯一事实源；改动一律按 L2 |
| `packages/engine` | 推荐引擎，纯函数零 IO；安全过滤永远先于评分 |
| `packages/list-merger` | 采购清单合并，纯函数 |
| `apps/api` | Fastify 5 + Prisma 7 + PostgreSQL；路由薄、逻辑在 services |
| `apps/h5` | Taro 4 + React + NutUI；勿引入 weapp 专属 API |
| `tools/content-pipeline` | 豆包起草 CLI；产物只能落 DRAFT 状态 |
| `docs/agents/` | 三个智能体提示词（改提示词先改这里并提交，再粘贴到 TRAE） |
| `evidence/T-xxx/` | 截图与原始输出（只存 L2 及以上，每份 ≤1 页报告） |

## 3. 常用命令（仓库根目录）

- `pnpm i`；`pnpm dev`（dev:api :3000 / dev:h5 :10086 / dev:admin）
- `pnpm lint`；`pnpm test`（纯逻辑单测，DB 集成测试需本机 PG）
- `pnpm test:taboo`（引擎禁忌集；引擎相关改动必跑，100% 阻断一票否决）
- 类型检查：`pnpm -r exec tsc --noEmit`（覆盖全部包，含 h5 与测试文件）
- `pnpm build`（= `pnpm -r build`）；`pnpm db:migrate` / `pnpm db:seed`

## 4. 风险分级（流程强度只看这张表）

| 级别 | 典型改动 | 必须做 |
|---|---|---|
| L0 | 文案、样式微调、注释、补测试、文档 | lint + typecheck + test 全绿；UI 改动附自动化截图 |
| L1 | 普通功能、缺陷修复 | 半页任务卡；缺陷先写失败测试；门禁全绿；一次独立审查（审查须实际跑命令）；页面自动化测试通过并截图 |
| L2 | 契约/数据结构、迁移、推荐或计算逻辑、安全规则、鉴权会话、缓存与部署配置 | L1 全部 + 影响清单 6 问 + 真实库集成测试 + 第 7 节不变量检查 + 验收环境预演 |
| L3 | 生产数据变更、发布、删除、不可逆操作、涉及费用 | L2 全部 + 备份 + 回滚脚本 + 产品负责人明确授权 + 发布后冒烟 + OPS-LOG.md 记一行 |

拿不准升一级；用户反馈的缺陷至少 L1；触及安全红线至少 L2。紧急修复可先修，24 小时内补齐对应级别检查。不给无边界授权。

## 5. 完成的五层（汇报必须写明第几层）

1 已实现（分支上门禁全绿）→ 2 已验证（审查通过 + 不变量 + 页面自动化截图；未达第 2 层不请产品负责人真机测试）→ 3 已发布（版本号 = 提交号）→ 4 用户确认 → 5 效果达成。"本地通过"只说第 1–2 层，不说"已修复"。

## 6. 固定设计规则（H5，每张卡默认生效，审查必查）

1. 不让用户输入系统编号（菜品 ID、计划 ID），一律点选或从相关页面带入。
2. 每个按钮都有反馈，禁止静默 return。
3. 枚举一律中文、时间本地格式、单位统一，由公共函数格式化。
4. 每个列表有加载 / 空 / 错误（可重试）三态。
5. 表单任何操作顺序都不丢已填内容。
6. 所有请求走统一封装（超时、网络错误、401 一处处理）。
7. 用 NutUI 组件 + 主题变量，不新增手写组件样式；UI 与功能同一张卡完成。

## 7. 系统不变量（L2+ 变更必须检查，对真实数据跑，不用夹具冒充）

- 任何 PUBLISHED 菜不违反任何 HARD 禁忌规则。
- 用户反馈作用在正确的对象上（同一道菜 / 同一套组合）。
- 规则引用的对象真实存在（targetId 不悬空）。
- 页面最后一个操作按钮完全可见。
- 生产构建产物不含本机地址、不含口令或密钥。

## 8. 红线

- 运行时代码禁止调用任何 LLM API；内容管线产物只落 DRAFT。
- 禁止引入：Redis、消息队列、微服务拆分、K8s。
- 不改 packages/shared，除非任务卡明确授权（契约变更按 L2 走影响清单）。
- 不把构建产物提交进仓库（packages/shared/dist 已入库属历史遗留，阶段 C 清理）。
- 不碰 .env 与 apps/h5/.env*；密钥、口令不入库、不进日志、不进证据文件。
- 不在生产服务器上做大构建；本服务器与买菜平台共用（内存、端口登记在 CURRENT.md 共用资源）。
- 测试不绿不提合并；失败了重跑直到通过 = 门禁作废，禁止。
- 工具或沙箱挡住标准操作时：停下来说明或请产品负责人执行，不伪造系统状态、不手改迁移记录。
- 同一时间只有一个会话在写同一工作区；并行工作各用自己的分支。
- 给产品负责人的操作指引（点哪里、填什么）必须先在实际页面或自动截图上行核对过。

## 9. Git 与文档

- 一任务一分支；产品负责人确认后合并 main 并推送 origin；提交标题 ≤72 字、动词开头，正文 ≤10 行。
- 状态更新与代码提交合并成一次提交，不单独提交"同步提交号"。
- CURRENT.md ≤40 行；任务卡 ≤半页；证据每份 ≤1 页；历史不进 CURRENT。
- 观察项（挂账）上限 10 条，每周清理；审查"建议级"意见默认不入账。
- 注释只写"为什么"，不写任务号和裁决；文档总字节超过源码时做减法。

## 10. 何时打断产品负责人

只在：产品含义有两种解释、UI 或体验需要选择、需要账号 / 费用 / 外部平台操作、正式环境 / 删除 / 不可逆操作。一次一个问题、普通中文、附推荐和默认做法。安全、费用、正式数据、不可逆四类不能按"跳过 = 默认"处理。

## 11. 智能体分工

主控 = TRAE 主会话（SOLO）：拆任务、派发、核对证据、维护 CURRENT.md；不在无人复核下执行生产变更。开发 fm-dev、审查 fm-reviewer、页面验收 fm-verify，提示词在 docs/agents/（改提示词先改仓库再粘贴）。主控职责全文见 docs/AI协作开发流程_V2.1.md 第 1 章。
